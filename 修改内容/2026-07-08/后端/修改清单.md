# 2026-07-08 后端修改清单

## 一、钉钉用户 / 部门同步

涉及文件：

- `pthonapi/routes/dingtalk.py`
- `pthonapi/services/dingtalk_sync.py`
- `pthonapi/scripts/sync_dingtalk_contacts.py`
- `pthonapi/scripts/apply_dingtalk_schema.py`
- `sql/dingtalk_contacts.sql`

主要修改：

1. 增加钉钉部门同步。
2. 增加钉钉用户同步。
3. 保存用户手机号、部门、部门层级路径等信息。
4. 支持最多四级部门结构。
5. 增加接口：
   - 手动同步钉钉通讯录。
   - 查询同步状态。
   - 查询部门。
   - 查询可选人员。
6. 同步策略：
   - 每天凌晨自动同步。
   - 后续可在管理端增加手动同步按钮。
7. 同步目标库：db2。

## 二、报工人员快照

涉及文件：

- `sql/mo_execution_workers.sql`
- `pthonapi/routes/mo.py`

主要修改：

1. 开工时保存当次选择人员快照。
2. 人员后续从钉钉删除或调整部门，不影响历史报工记录。
3. 支持正式员工 + 临时工。
4. 临时工保存为临时工1、临时工2、临时工3……。
5. 校验：不允许只选择临时工。

## 三、接收功能

涉及文件：

- `sql/mo_receive_work_yx.sql`
- `sql/mo_receive_work_yx_add_photo_url.sql`
- `sql/mo_receive_work_yx_add_qty_ac.sql`
- `pthonapi/routes/mo.py`

主要修改：

1. 新增接收作业记录表。
2. 新增接收人员快照表。
3. 接收逻辑调整为：
   - 当前可接收 = 上工序完工数量 - 当前工序已接收数量。
4. 接收时记录：
   - 接收数量
   - 接收原因
   - 接收人员
   - 接收照片
   - 接收时间
5. 接收完工时记录：
   - A 级数量
   - C 级数量
   - 完工时间
6. 接收完工后更新工单/工序总结束时间，并重新计算用时。
7. 支持多次接收历史展示。

## 四、返工功能

涉及文件：

- `sql/mo_rework_yx.sql`
- `pthonapi/routes/mo.py`

主要修改：

1. 新增 C 级品返工记录表。
2. 新增返工人员快照表。
3. 返工开工记录：
   - 返工投入数量
   - 返工原因

## 五、开工 / 完工 / 数量校验

涉及文件：

- `pthonapi/routes/mo.py`
- `sql/mo_v2.sql`
- `sql/mo_v2_patch2.sql`

1. 完工支持备注。
2. 异常完工强制填写说明。

5. 分批接收逻辑曾尝试，后续按要求取消，保留更简单的接收逻辑。

## 七、工艺路线调整

涉及文件：

- `pthonapi/scripts/apply_reporting_routes_v2.py`
- `pthonapi/scripts/sync_product_routes.py`
- `sql/mo_product_route_yx.sql`
- `sql/mo_v2.sql`

主要修改：

1. 报工路线和报价路线分离，避免报工调整影响报价成本。
2. 双面肤感类重复工序合并：
   - 例如修补 → 修补 合并为修补。
   - 肤感烤漆 → 肤感烤漆 合并为肤感烤漆。
3. 补齐 HPL 相关路线中的“粘贴垫板”工序。
4. 路线保留启用/禁用思路，避免直接删除历史可能使用过的路线。
5. 后端删除规则调整方向：
   - 只有 admin 可以删除。
   - 只能删除没有使用过的工艺路线。
   - 已使用路线的历史报工不应被后续顺序调整影响。
