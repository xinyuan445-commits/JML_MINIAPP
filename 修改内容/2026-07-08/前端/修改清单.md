# 2026-07-08 前端修改清单

## 一、报工 / 完工记录页面

涉及页面主要在：

- `JML_WX_miniapp/Mo/ProcessMgmt/Detailed.js`
- `JML_WX_miniapp/Mo/ProcessMgmt/Detailed.wxml`
- `JML_WX_miniapp/Mo/ProcessMgmt/Detailed.wxss`
- `JML_WX_miniapp/Mo/ProcessMgmt/Index.js`
- `JML_WX_miniapp/Mo/ProcessMgmt/Index.wxml`
- `JML_WX_miniapp/Mo/ProcessMgmt/Scanner.js`

主要修改：

1. 完工记录明细增加“用时”显示。
   - 根据开始时间、结束时间自动换算。
   - 支持“不足 1 分钟 / 分钟 / 小时 / 天”等显示。

2. 完成记录支持继续流转。
   - 有下一步工序时，明细里可以进入下一步。
   - 解决“已完成列表点进去看不到完成内容 / 后续工具”的问题。

3. 按钮布局多次优化。
   - “进入下一步”作为主按钮，宽度更大。
   - “接收 / 返工”等辅助按钮放在上方一行。
   - 避免按钮堆叠过高、视觉过重。

4. 历史记录展示优化。
   - 接收记录、返工记录做成更清晰的记录块。
   - 解决多次记录混在一起、不好区分的问题。
   - 背景色从偏黄的大块样式调整为更轻的卡片风格。
   - 后续适合继续做折叠展示。

## 二、人员选择

主要修改：

1. 开工、返工、接收等环节支持选择人员。
2. 人员来源改为钉钉同步人员。
3. 部门选择改为一级一级选择，避免所有部门/人员堆在一起。
4. 只显示指定部门范围：
   - 金米龙
   - 科米龙
   - 金米龙江苏
5. 增加“临时工”选择。
   - 临时工和金米龙、科米龙放在同一级入口。
   - 用户自己选择临时工数量。
   - 显示为：临时工1、临时工2、临时工3……
6. 增加限制：不允许只选择临时工，必须至少选择一个正式人员。

## 三、接收功能

主要修改：

1. 将原“下线”概念调整为“接收”。
2. 接收数量逻辑调整为：
   - 本次可接收数量 = 上工序完工数量 - 当前工序已接收数量。
   - 显示重点改为“剩余可接收数量”，减少信息占用空间。
3. 接收弹窗优化。
   - 接收数量输入区域更明显。
   - 不再让用户容易点到提示文案。
4. 接收时需要选择接收人员。
5. 接收时需要拍照留底。
   - 后续工序领用/接收必须拍照。
   - 第一道工序没有领用，但需要做“主材拍照”。
6. 接收后按钮变为“接收完工”。
7. 接收完工时支持填写 A / C 数量。
8. 接收完工后，总结束时间回写为最新接收完工时间。

## 四、返工功能

主要修改：

1. 明细页增加“返工”按钮。
2. 返工对象是 C 级品。
3. 返工开工需要填写返工数量和说明。
4. 返工需要选择人员。
5. 返工完工需要填写：
   - A 级数量
   - C 级数量
   - 备注
6. 返工完成后重新计算完工用时。
7. 总结束时间回写为最新返工完工时间。

## 五、开工 / 完工校验

主要修改：

1. 报工界面的“补工”已移除。
2. 明细界面的“补工”改为“下线”，后续又调整为“接收”。
3. 完工支持备注。
   - 正常完工备注不强制。
   - 异常情况需要强制填写说明。
4. 超过计划数量或历史累计数量超过计划时，需要填写原因。

## 六、拍照复用

参考来源：

- `JML_WX_miniapp/factory/pages/kaiguandengji`

主要修改：

1. 将已有拍照上传能力复用到报工接收场景。
2. 接收时拍照，不是接收完工时拍照。
3. 第一道工序做主材拍照。
4. 后续工序接收/领用必须拍照。

## 七、工艺路线前端相关

主要修改：

1. 工单列表展示当前路线/部门信息。
2. 无路线、待接收、进行中、已完成等状态展示更清晰。
3. 管理后台的工艺路线调整不在当前小程序仓库内，需后台项目单独留档。
