# 工序管理设备管理方案

更新：2026-10-22。

状态：已按最新要求改为独立设备档案，不读取或关联原 `jml_device`。实际业务库先按32个现有工站建立同名设备，后续新增3组基础资料，当前35个工站对应35台独立设备；2026-10-30按最新清单更新设备名称后共有17条启用标准。设备入口在“工序配置”；本地运行与验收记录见第15节，标准维护见第16、17节，历史测试记录见第14节。维修流程保持不动。

关联资料：[管理后台交接](管理后台交接20261022.md)、[后台权限管理](后台权限管理.md)、[工序管理相关数据表](工序管理相关数据表.md)、[小程序工序管理交接](../../docs/工序管理交接20261022.md)。

## 1. 目标与范围

用户已确定按“一个工站对应一台设备”设计，第一步维护独立设备档案和标准产能。最新要求覆盖此前“关联原设备”的方案：设备由本页面新建，与原设备表独立；本次按已有工站建立同名设备。支持按小时、天、班等时间口径填写产能，并明确支持无限产能。

第一步包含：

- 管理后台“工序配置 → 设备管理”页面。
- 工站与独立设备的一对一关联，以及设备生产档案。
- 按设备、工序、产品类别维护有限或无限产能标准。
- 时间换算预览、参考加工用时计算。
- 新增、修改、启停和关联调整的权限、审批、版本校验及变更记录。

维修流程保持现状：不调整报修、派单、接单、维修进展、完工、认可、通知或原维修权限，不自动根据维修单改变工站或设备状态。

本期不做自动排产、交期承诺、班次日历、设备联网采集、设备效率计算、维修停机联动，也不调整现有接收、开工、完工和报表统计规则。原先讨论的“顶部计划按工单行去重”与设备管理无关，仍未实施。

## 2. 系统边界与设备来源

| 内容 | 所属位置及处理方式 |
| --- | --- |
| 管理页面、设备档案和标准产能接口 | `jml_admin/src/pages/mo/`、`jml_admin/webapi/` |
| 现有工站、路线及工站权限 | 保留现有工站标识和关联方式，不用设备标识替换 |
| 独立设备资料 | `mo_equipment_device_yx`，自行新建、维护名称、编号、启停及生产属性；不读取或关联 `jml_device` |
| 小程序报工服务 | `JML_MINIAPP/pthonapi`，本期不因新增后台档案而修改现场报工流程 |
| 现有设备维修 | 沿用原服务和数据关系，不把维修接口或认证移入 WebAPI |
| Web与小程序看板 | 各自规则保留；本期不自动增加设备字段或更改刷新、分页、数量和权限逻辑 |

设备身份由独立的稳定 UUID 标识，设备编号唯一，名称允许修改或重名；关联不依赖名称。原 `jml_device` 仍仅由其原业务使用，新增设备不写入原设备表，也不成为维修设备。

本次按现有工站ID建立设备与关联，名称默认与工站相同。后续名称可独立修改，不随工站改名自动联动。管理后台仍使用现有业务 MySQL 连接与后台认证，不调用维修接口或复用维修令牌。

## 3. 工站与设备关联

- 一个工站最多有一个当前设备关联，一台设备最多关联一个当前工站。本次明确初始化已有工站；以后新建工站不会在服务启动时自动生成设备，新增档案选择工站时默认同名。
- 新关联仅选择当前可用的工站、设备。已经关联但后续停用的记录仍可查看，明确显示来源状态，不自动删除关联或历史。
- 选择设备时显示名称和可用的编号；重名时增加稳定标识用于区分。
- 已被其他工站关联的设备显示当前占用工站，不允许重复关联；审批生效时再次检查，不能只靠下拉列表过滤。
- 不改变原工站的线长、扫码人员、豁免、代理或路线工站关系。
- 已有档案更换设备走关联调整申请；审批通过时记录原设备、新设备、实际生效时间及操作人。第一步只支持审批通过时生效，不增加预约或倒填生效功能。
- 换机后旧设备的产能标准不自动复制给新设备，新设备未配置标准时显示“未配置”。
- 保留关联变更历史，不把旧报工全部解释为当前设备生产。没有可靠历史关联的旧记录不反推设备，不回填或改写报工流水。

## 5. 标准产能字段

一台设备可以针对不同工序、产品类别维护多条标准。标准随设备保存，工站用于定位当前设备，不把产能写到工序主数据上。

| 字段 | 要求 | 规则 |
| --- | --- | --- |
| 所属设备 | 系统关联 | 绑定独立设备 UUID，不依赖设备名称 |
| 适用工序 | 必填 | 复用现有工序，优先列出当前工站已配置可执行的工序；需要使用新工序时先维护原路线配置 |
| 适用产品类别 | 选填 | 复用现有报工类别的稳定标识；空表示该工序的通用标准 |
| 适用规格说明 | 选填 | 如“厚度≤3mm”；第一步只作条件说明，不实现自由文本规格自动匹配 |
| 产能模式 | 必填 | 有限产能、无限产能 |
| 标准数量 | 有限时必填 | 大于0的十进制数；无限模式为空 |
| 计量单位 | 有限时必填 | 如件、套、米、公斤；统一选项，优先核对并复用现有产品单位；无限模式可留空 |
| 时间周期 | 有限时必填 | 每分钟、每小时、每天、每班；原始口径保留，不只保存换算结果 |
| 周期有效工时 | 按天或班时必填 | 大于0且不超过24小时，允许小数；按分钟、小时不填；无限模式为空 |
| 标准配员 | 建议填写 | 正整数或未知；表示达到标准的人员条件，不把总产能再乘一次人数 |
| 换型准备时间 | 选填 | 分钟/次，大于等于0；留空表示未知，0表示确认无需准备 |
| 标准依据 | 必填 | 经验估算、现场实测、厂家参数 |
| 测定日期 | 选填 | 现场实测或评估日期 |
| 启用状态 | 必填 | 启用、停用；正式变更走审批 |
| 备注 | 选填 | 材料、模具、操作条件等 |
| 修订、生效及审计信息 | 系统记录 | 保留原值、申请人、审批人、生效时间及版本 |

### 5.1 适用与唯一性

- 同一设备、工序、产品类别最多一条当前启用标准；通用标准按独立的空类别处理，也只能有一条当前启用记录。
- 有明确类别标准时优先使用该标准，否则使用通用标准；都没有时为未配置。
- 类别标准停用后不再参与选择；如仍有启用的通用标准，可使用通用标准，并显示实际采用的标准。
- 规格说明不参与自动匹配。同类别内不同规格差异很大时，不能悄悄套用同一个数字；需要后续增加明确的规格区分后再支持自动选择。
- 数量换算只在同一计量单位内进行，件、套、米、公斤之间没有已确认转换关系时不得换算或相加。
- 标准数量采用正常完工总数量口径，返工不重复计入；不自动把标准产能当作良品产能，不改变现有A、A1、A2、C质量统计规则。
- 设备停用、工站停用、标准停用是不同事实。保留标准资料，但不把停用设备标为当前可用于生产。

## 6. 有限产能与时间换算

### 6.1 原始输入与统一换算

用户可以直接填写“400件/天”，同时填写“每天有效工时8小时”。“天”表示该标准约定的一个生产工作日，不默认等于24小时；“班”表示一个班次，不默认等于8小时。

设标准数量为 Q，一个周期的有效分钟数为 M：

| 原始周期 | M的取值 |
| --- | --- |
| 每分钟 | 1 |
| 每小时 | 60 |
| 每天 | 当条标准的每日有效工时 × 60 |
| 每班 | 当条标准的每班有效工时 × 60 |

换算公式：

```text
标准小时产能 = Q × 60 ÷ M
单计量单位标准用时（分钟） = M ÷ Q
指定数量N的参考加工用时（分钟） = N × M ÷ Q
```

有效工时表示该标准约定的生产时间，应明确休息等固定非生产时间是否已经扣除。不使用上班打卡时长或报工起止时间自动代填。每日工时改变时，通过修改标准并审批形成新修订，不能因全局设置变化悄悄改写旧标准。

### 6.2 示例

以下均为示例数据，不代表任何真实设备标准。

| 输入 | 标准小时产能 | 单件用时 | 100件参考加工用时 |
| --- | --- | --- | --- |
| 400件/天，8小时/天 | 50件/小时 | 1.2分钟 | 120分钟，即2小时 |
| 400件/天，10小时/天 | 40件/小时 | 1.5分钟 | 150分钟，即2.5小时 |
| 400件/班，8小时/班 | 50件/小时 | 1.2分钟 | 120分钟，即2小时 |
| 120件/小时 | 120件/小时 | 0.5分钟 | 50分钟 |
| 2件/分钟 | 120件/小时 | 0.5分钟 | 50分钟 |

“400件/天、8小时/天”下，100件为0.25个标准生产日，不等于自然日6小时，也不能据此承诺当天完成。

### 6.3 准备时间、精度与未知值

- 参考加工用时只包含按产能折算的加工时间，不默认包含换型、排队、休息、停机、跨班等待或物流时间。
- 换型时间单独展示。第一步不自动给每张工单加一次准备时间，因为一次换型可能连续生产多张工单。只有明确准备次数后，才可按“加工用时＋准备次数×单次准备时间”给出参考合计。
- 标准配员是适用条件，不按人数自动线性放大产能。
- 保留原始数量、单位、周期和有效工时，用十进制计算；不要先四舍五入小时产能再计算用时。
- 页面默认显示最多4位小数并去掉末尾0；正数小于0.0001时显示“<0.0001”，不能显示成0。时间可同时给出分钟及小时便于理解。
- 指定数量必须大于0，且单位与标准一致；这只是参考计算，不写入工单或业务流水。
- 有限模式缺少有效工时等必填项时不能保存，预览显示待填写；已有资料缺项时显示待补，不猜测8小时或24小时。
- 前端可实时预览，后端必须独立校验并作为正式换算口径；两端用相同示例验证一致性，不接受前端直接提交的换算结果作为事实。

## 7. 无限产能与未配置

“无限产能”是明确选择的业务模式，含义为：该设备在此工序、产品类别上的标准不作为未来排产的产能约束。第一步保存并展示该选择，不因此新增排产系统。

| 情况 | 页面显示 | 数量、周期、有效工时 | 参考加工用时 |
| --- | --- | --- | --- |
| 有限标准完整 | 400件/天等原始口径 | 保存实际值 | 按公式计算 |
| 明确无限 | 无限产能 | 为空，不存超大值或无穷数 | “—”，不显示0分钟 |
| 没有适用启用标准 | 未配置 | 没有当前可用标准 | “—” |
| 资料缺项或错误 | 待补 | 保留问题信息 | 不计算 |

- 未配置、已停用、读取失败都不能当作无限产能。
- 无限不代表产品瞬间完成，也不绕过工单计划、数量校验、权限或照片要求。
- 无限模式保留适用工序、产品类别、标准依据及备注；配员、换型资料可以保留为条件说明，但本期不据此推导总用时。
- 从有限切换为无限后，正式记录中的数量、周期、周期有效工时清空为未知/不适用；旧数值保留在修订历史，不藏在当前标准中继续参与计算。
- 从无限切换回有限时，重新填写并校验数量、单位、周期及必要工时，不静默恢复旧标准。
- 如果实际需求是“可并行处理很多工单，但每批固定需要2小时”，属于固定加工时长和并发能力，不能用无限模式推导0用时；待后续明确需求再设计。

生产报表2的工序悬停框已接入该换算口径。标准任务数量取该工序累计正常接收量；有限产能按“接收量 × 单位标准分钟”得到标准任务时间，再用首次开工至当前或末次完工的实际历时计算时间百分比。实际历时是报工时间跨度，可能包含跨班等待、休息或停机，因此允许超过100%；该比例用于对照，不反写报工或产能档案。现有报工步骤没有独立的工序计量单位，换算时把该工序接收数值按所选产能标准单位解释，并在进度条下显示该单位，不自动执行“张转面”等倍数换算；如后续需要一张对应两面等规则，须增加明确转换系数后再计算。无限产能、未配置、停用或资料缺项均不显示时间百分比。

## 8. 页面方案

本地已注册入口“工序配置 → 设备管理”，路径 `/mo/equipment`、页面目录 `src/pages/mo/equipment/`。按用户后续要求从“工序管理”调整到“工序配置”，URL和设备权限不变；实际启用记录见第15节。

### 8.1 列表

查询项：关键词（工站编码/名称、设备编号/名称）、设备类型、车间、工站启用状态、设备启用状态、是否已配置启用产能标准。

主要列：

| 列 | 显示方式 |
| --- | --- |
| 工站 | 编码、名称 |
| 设备 | 独立设备名称、编号 |
| 类型、车间、型号 | 简短展示，未知显示“—” |
| 工站状态、设备状态 | 分别展示来源状态 |
| 产能配置 | 未配置、已配置N条；N为当前启用标准条数，不随意挑一条代表整台设备 |
| 申请状态 | 待审批、已驳回；与来源启用状态分列 |
| 操作 | 查看、编辑申请；按权限和申请状态展示 |

顶部主要操作为“新增档案”。第一步不增加无明确需求的导出、批量导入或维修操作按钮。

### 8.2 详情抽屉

两个页签：

1. **设备档案**：工站关联、独立设备资料、生产属性、照片、启停状态和变更记录。
2. **标准产能**：当前设备的标准列表，展示工序、类别、模式、原始产能、周期工时、配员、依据、启用及审批状态。支持新增、编辑、启停和查看修订记录。

设备列表操作区明确分为“编辑档案”和“产能设置”。“产能设置”直接打开当前设备详情的“标准产能”页签；两类资料仍分别执行档案和产能权限、审批及历史记录。

有限标准详情提供“换算”区域：显示小时产能、单计量单位用时，输入指定数量后预览参考加工用时。无限模式显示无限产能，参考用时为“—”；没有适用标准时显示未配置。

### 8.3 表单与流程

新增档案：选择工站 → 默认新建同名设备（编号默认 `EQ-工站编码`），或选择已有独立设备 → 补齐资料 → 提交审批 → 审批通过后进入正式档案。本次按工站批量初始化是用户明确要求的一次性建档，直接记录初始化历史；以后页面维护仍走审批。

正式档案建立后才能添加产能标准。档案与标准分别申请，避免档案尚不存在时先产生正式标准。

产能表单顺序：

1. 工序、产品类别、规格说明。
2. 产能模式。
3. 有限时显示数量、单位、时间周期；按天/班显示有效工时。
4. 标准配员、换型准备时间、依据、测定日期、备注。
5. 有限且输入完整时显示换算预览，提交后走审批。

无限模式隐藏数量和时间输入，不在表单堆放长篇解释。字段旁只保留必要的短提示，如“按有效生产时间填写”；完整口径留在本文档。

## 9. 权限、审批与历史

- 继续使用现有后台账号及双登录，不新建设备登录，不以 `jml_staff` 现场身份代替后台账号。
- 新增独立的设备查看、档案新增/编辑、产能维护、审批权限，具体标识实施时统一注册；授予操作权限应包含对应查看权限。
- 设备页面纳入现有全局页面开关；平台 `production-view` 仍受只读上限限制。
- 工站线长、扫码、豁免、代理不自动获得后台设备维护权；后台设备维护权也不授予现场报工权或维修权。
- 扩展原配置审批机制，不建立第二个审批中心。档案新增/编辑、工站关联调整、标准新增/编辑/启停先申请，审批通过才改变正式资料。
- 待审、驳回数据在页面明确标记，不作为生效标准。允许申请人按现有规则修改或重新提交，保留审批结果已读机制。
- 申请与审批均检查修订版本；审批时重查设备/工站可用性、关联唯一性和产能唯一性，防止并发申请生效后冲突。
- 档案、标准编辑及标准启停必须携带正式资料 `revision`；提交/修改申请及审批落库均核对，不允许旧页面把申请前已更新的正式资料覆盖掉。原申请本身另有审批 `revision`，两者分别传递，不能混用。
- 正式写入、审批状态变更和后台审计在同一事务中完成；失败整体回滚。
- 不硬删除已使用档案、标准或历史。标准修改和关联调整保留生效时间、前后快照、真实申请与审批账号。
- 当前设备名称可通过档案审批修改，历史快照保存当时名称，不能批量改写旧记录。
