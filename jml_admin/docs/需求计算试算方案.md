# 需求计算只读试算

更新：2026-10-23。当前实现位于管理后台 `jml_admin`，不修改小程序报工服务。

## 当前范围

“需求计划 → 需求计算”已经接入U8销售订单、BOM、MRP仓库存量、采购未到货和生产未完工数据，并结合本地工艺路线、独立设备及标准产能进行只读试算。页面和接口不保存计算方案，不写入ERP；结果中的采购单和工单编号均为试算编号，不是ERP正式单据。

页面先按销售订单日期查询未关闭、未交完且已审核的销售订单行，当前查询最多返回500行并可一次全部选择试算。页面各表不分页，使用滚动查看。试算结果分为生产需求、物料需求、供需关系、设备排程和异常五部分。

## 生产净需求

同一产品的可用成品库存按交期、订单号和行号顺序分配，不能被多条销售订单重复抵扣。生产供应只使用与销售订单行关联、已审核且未关闭的生产订单剩余数量。

```text
销售未交数量 = 订单数量 - 已发货数量
建议生产数量 = 销售未交数量 - 已分配成品库存 - 已关联生产供应
```

物料需求优先显示需要采购、生产或待确认的记录；净需求为0的记录集中放入默认收起的“无需下单”区域。物料主行显示净需求、最终结果、建议数量和试算单号，展开物料行后列出该物料所有正数库存仓库，以及全部已审核、未关闭且未收满的采购明细；同时显示现存或未收数量、本行抵扣量和抵扣后余额。晚于需求日期的采购单保留展示但不参与本行抵扣。页面不显示MRP仓库属性，试算按各仓库正数现存量依次分配，不使用U8当前为0的可用量字段，负数按0处理；成品抵扣后的仓库余额继续供物料需求使用。

## 物料需求

使用试算日有效、状态为已审核的最新版BOM，最多展开10层，并检查循环引用。父项损耗、子件损耗和BOM分子/分母参与用量换算。多层BOM按层计算：每个自制半成品先扣除库存、到期采购和未完工生产供应，只把剩余生产净需求继续展开到下一层；采购件、无需下单的半成品和没有有效BOM的物料停止向下展开。

物料按“物料编码＋需求日期”汇总。同一物料的库存和在途供应按日期顺序分配，采购与生产供应只有在预计到货/完工日期不晚于需求日期时才可抵扣。安全库存只在该物料第一个需求日期加入一次；最小供应量、供应倍数和提前期用于计算建议数量与建议下达日期。

```text
物料毛需求 = 父项计划数量 × BOM单位用量 × 损耗
物料净需求 = 毛需求 + 安全库存 - 已分配库存及到期供应
下层物料毛需求 = 上层自制半成品净生产需求 × BOM单位用量 × 损耗
```

物料只标记自制时建议“生产”，只标记外购时建议“采购”。U8中大量物料同时勾选自制和外购：双属性物料存在试算日有效BOM时建议生产，没有有效BOM时建议采购。两者均未标时显示“待确认”。

## 供需关系与试算编号

销售订单以“销售订单号＋行号”区分需求，同一销售订单的不同产品行不会合并身份。物料需求按“物料编码＋需求日期”汇总计算，但供需关系仍按来源销售订单行拆分数量，因此可以从建议单追溯到具体销售订单行。

供应按需求日期、销售订单号和行号顺序分配，优先满足较早需求。成品库存抵扣后的余额继续供物料需求使用，同一物料不会因兼具成品和子件身份重复使用库存。库存、现有采购单和现有生产工单一经分配即扣减可用量，不会再次供应其他订单；已绑定销售订单行的现有工单只供应该销售行，不进入通用物料供应池。采购供应只匹配已审核、表头未关闭、明细未关闭且订单数量大于累计入库数量的采购明细，并保留采购单日期和预计到货日期。一个供应单满足多个需求时，供需关系表按需求分别显示分配数量。

本次试算需要新增单据时，按稳定排序生成：

```text
采购建议：POyyyymmdd0001、POyyyymmdd0002……
生产建议：MOyyyymmdd0001、MOyyyymmdd0002……
```

PO和MO各自使用四位流水号，生产编号同时覆盖销售成品建议工单和自制半成品建议工单。编号只在本次试算结果中存在；重新试算会按当次试算日期和结果重新编号。最小供应量或供应倍数造成的建议超量显示为建议量的一部分，供需关系只挂钩实际净缺口，超出部分暂不分配给订单。

供需关系按实际分配逐行显示，每一行只配对一条需求和一个供应来源。一个需求由多项供应共同满足时拆成多行，例如库存供应一部分、采购单供应另一部分；每行直接显示需求单、需求行、物料、需求日期、供应类型、供应单或仓库、供应日期和分配数量。试算单使用醒目标识，不能作为ERP正式单号引用。

## 工序工时与设备倒排

产品按U8物料类别匹配本地当前工艺路线，再按路线步骤、允许工站、工站独立设备和启用中的标准产能计算。类别专用标准优先，通用标准兜底。

```text
标准工时 = 建议生产数量 ÷ 标准数量 × 标准周期分钟 + 准备时间
```

有限产能任务从销售交期按工艺顺序向前倒排，同一工站同一天不能超过该标准的有效工时。当前按自然日排程，尚未接入班次、节假日、停机和已锁定现场任务。无限产能保留工序顺序但因尚无流转时间字段，当前按零流转时间试算并列入异常。

订单计量单位与产能单位必须完全一致才计算工时。例如订单单位是“张”、产能单位是“面”时不会默认按一张两面换算，而是标记单位不一致。后续需要建立产品或类别维度的工序单位换算后才能消除这类异常。

## 接口和权限

- `GET /api/demand/sales-orders`：查询可参与试算的销售订单行。
- `GET /api/demand/calculate`：按销售订单行即时计算并返回结果。
- 两个接口都只需要 `demand-calculation.view`，同时受 `demand-calculation` 页面开关控制。
- 没有需求计划数据表或初始化脚本；重复试算不会产生业务数据。

## 当前限制

- 只对建议新增的生产数量展开工序，不重排已有生产订单。
- 多层BOM已经逐层净算，半成品库存和到期供应会减少更低层物料需求；下层物料目前仍追溯到来源销售订单对应的成品试算工单，尚未在供需关系中改挂每一层父项半成品试算工单。
- 尚未把BOM各层提前期逐层传递到子件需求日期；当前子件沿用销售交期，建议下达日期再扣物料提前期。
- 尚未维护工作日历、班次、设备停机、换型矩阵和人工资源约束。
- 工站有多个允许设备时，当前优先选择能匹配类别和单位的启用标准；尚未做多设备并行优化。
- 结果用于核对数据和讨论口径，不能作为已确认生产或采购指令。

后续调整上述规则时，应同步修改 `webapi/demand_calculation.py`、需求计算页面、权限测试、本文件和管理后台交接文档。
