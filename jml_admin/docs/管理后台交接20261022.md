## 路径和启动

2026-11-06修复打开工单路线指定时偶发503：页面及导航的并发读请求超过WebAPI五个MySQL连接时，原 `get_connection()` 直接抛出连接池耗尽异常，权限校验将其转换为503。共享 `db()` 改为仅对连接池耗尽等待最多5秒、每50毫秒重试获取；其他数据库异常仍立即抛出，权限失败增加服务端异常日志，不绕过权限或增加数据库写入。并发回归使用隔离Flask只读请求，未创建测试审批或修改工单。

- 前端：React、Umi Max、Ant Design Pro；入口配置 `config/routes.ts`，运行时 `src/app.tsx`，权限 `src/access.ts`。
- 实际后台API：项目内 `webapi/app.py`。不要修改根目录旧 `webapi` 或把小程序 `JML_MINIAPP/pthonapi` 当成后台API。
- `npm start` → `scripts/start-with-webapi.js`：先检查/启动5001的WebAPI，再启动8886无mock前端，并启动代理到期清理和报表邮件定时任务。已有健康WebAPI直接复用，不会在退出时关闭该外部进程；本次启动的子进程退出时一并停止。
- `WEBAPI_PYTHON` 可指定Python解释器；`npm run start:frontend` 只启动8886前端，`npm run dev` 也不负责启动WebAPI。
- 2026-11-09，Windows 下可在另一个终端执行 `powershell -ExecutionPolicy Bypass -File .\scripts\restart-frontend.ps1` 单独重启 8886 前端，或执行 `powershell -ExecutionPolicy Bypass -File .\scripts\restart-backend.ps1` 单独重启 5001 WebAPI。两者通过项目专用命名管道通知 `npm start` 启动器，只重启指定的子进程。首次使用时，在原终端用 Ctrl+C 停止旧启动器，再运行一次 `npm start`。如果 5001 由其他启动器提供，回到它的启动窗口重启。
- 也可直接双击 `scripts/restart-frontend.bat` 或 `scripts/restart-backend.bat`。窗口显示重启结果后会等待按键关闭。
- 首页进入生产大屏。大屏“返回”会把进入后台的目标传给登录页，登录完成后进入当前账号有权限的管理页面。已有登录会话时，先同步前端登录状态，再直接进入后台。
- 开发环境 `/api/` 在 `config/proxy.ts` 转发到 `127.0.0.1:5001`。静态部署不能依赖开发代理，须单独配置反向代理及API进程。
- `scripts/restart-production-headless.ps1` 是本地重启脚本，会终止识别到的启动器并隐藏窗口重启，要求OIDC已开启；只在明确要求重启时使用，不能作为只读检查。
- 代理清理脚本会删除过期授权并写审计；不要为检查启动方式而随便运行。

当前已按用户要求执行本地权限初始化并重启8886/5001，未部署远程后台、上传小程序、提交或推送。源码具备某功能不等于线上已更新，下一次部署前须核对当前进程、文件、数据库和运行配置。当前 `jml_admin` 目录未被Git识别为仓库，不要擅自初始化仓库或套用小程序的main推送流程。
