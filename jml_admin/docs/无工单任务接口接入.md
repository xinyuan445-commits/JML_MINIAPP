# 无工单任务后台接入

2026-11-15：第5阶段已接入本地 WebAPI 和后台页面。当前安排单支持无工单新建、混合保存和同一文件 Excel 导出。

`webapi/nonorder_api.py`注册`/api/nonorder/*`及`/api/admin/accounts/staff-binding`。数据与业务规则复用`JML_MINIAPP/nonorder_shared`；PythonAPI和WebAPI分别用现有DB2连接，无第三套凭据。

无工单权限为 `nonorder.view/manage/publish/review/transfer/view-all/manage-all`，按角色单独授予。页面入口与 daily-tasks 关联。核对需要当前有效员工绑定和具体任务授权。专门交接和后台发布可以根据各自权限由未绑定员工的账号操作。绑定由 accounts.manage 显式操作，唯一且带版本，前后值写既有审计。

- 安排单读取在授权后返回 `nonorder.candidates/items/history`。列表单列 `nonorder_count`。候选和安排使用带来源的标识，现有工单字段继续沿用。
- `POST /api/mo/daily-tasks/save` 的 `action=batch_sheet` 可携带 `nonorder_changes`。每条变更带任务、指派版本，操作已保存安排还需安排编号和版本。操作为 `add/update/cancel/reschedule/append`，改期和追加带 `target_date`。只保存无工单时使用 `nonorder_only=true` 和空 `batches`。混合操作与历史事件共用事务，跨日或校验失败整批回滚。
- `GET /api/nonorder/daily-result?date=YYYY-MM-DD` 按执行日期返回锁定原值或当日结果及后续核对、修正。无安排单可以查询。快照进程独立扫描应冻结日期，GET 只读。核对和交接使用 `/api/nonorder/command`，复用原有业务规则。
- `GET /api/admin/accounts/staff-binding?id=...` 返回关联员工、绑定版本和可选员工，POST 保存关联或解除。账号管理、安排、核对和交接分别执行权限校验。
- `GET /api/nonorder/publish-options` 返回负责人和工作类别，传 `responsible_staff_id` 查询该负责人的工站、执行人员及核对候选。安排单保存可带 `nonorder_creations`，每项包含 `request_id` 和 `task`。服务端在同一事务创建任务、分工、指派和当前单据的日安排；`nonorder_publish=true` 同时生效，否则保留服务器草稿。新任务记录实际后台账号并复核权限。旧 `create_and_publish` 调用仍可用于单独发布任务。
- 页面通过 `/api/mo/daily-tasks/export?date=YYYY-MM-DD&scope=day` 合并该执行日的主单和补充单，工单和无工单在「任务安排」工作表中分上下两块，两类任务标注来源单据。原请求不传 `scope=day` 时按具体 `sheet_id` 导出单张安排单。带部门参数时只返回对应工单明细。
- 按执行日期打印时，同一接口增加 `format=print`，返回 Excel 共用的表头、明细和工站合并信息。页面用该数据渲染 A4 打印预览。

2026-11-16：后台发布的负责人候选仅包含未列入豁免名单的有效线长。查询指定负责人的候选数据、保存任务草稿、正式发布任务时分别校验。核对人候选及已发布任务的授权沿用原规则。

2026-11-17：安排人员数据返回 `can_edit_work`。 `GET /api/nonorder/sheet-work-people` 按指派编号返回可选执行人员。保存安排的 `add/update` 可携带 `work_edit`，在同一事务内验证版本、修改任务及日安排。换人取消原指派的当前日安排并保留记录；新安排继承执行日期及发布状态。

WebAPI 与快照进程使用既有 `NONORDER_ENABLED=1` 开关和现有9表结构；附件需要访问小程序报工服务使用的同一私有附件存储。第5阶段的操作及验证见[工站每日任务](工站每日任务.md)。
