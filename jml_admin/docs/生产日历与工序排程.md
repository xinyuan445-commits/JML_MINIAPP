# 生产日历与工序排程

更新：2026-11-11。对应管理后台本地实现。

## 当前范围

- 生产现场看板的 `admin` 用户可在“当前看板”和“工序进度”之间切换；其他登录用户和未登录访问只显示当前看板，排程试算接口同时拒绝访问。
- 工序进度使用分组时间轴展示，每道工序作为一个分组，同一工序下排列不同工单任务；普通重叠任务自动上下错层，密集重叠任务自动合并为数量块，双击数量块可放大展开。左侧固定显示工序名称、对应工站、设备、任务数和逾期数，任务条显示工单号、行号与数量。
- 时间轴默认定位到当前日期附近，可放大、缩小、回到今天或查看全部排程；周末显示底纹，当前时间显示竖线。任务颜色区分实际完成、试排、预计逾期和无限产能。
- 计划开工、计划完工属于工单级日期，不在每道工序上常驻重复绘制；鼠标悬停具体任务条时，仅在该工序行临时显示计划日期的浅蓝虚线范围、蓝色“开”和红色“完”端点。彩色任务条的长度及条内时间表示按产能、生产日历和设备占用换算出的本工序实际/预计加工时间；分区详情同时显示精确日期、标准产能、任务数量、任务用时和异常。
- 时间轴默认显示7天，可切换14天或全部范围，仍支持今天、放大和缩小。
- 工序进度只读取当前看板中的未关闭工单，按生产日历、标准产能、工序先后和设备占用即时试排。
- 日历、默认策略和工序交割规则可保存。试排从生产现场看板进入，结果不保存，也不接入需求计算。
- 一工站对应一设备，同一工站任务串行，不同工站并行。
- 有限产能按“剩余计划数量 × 单位标准用时”换算；无限产能显示节点，不占设备排程时间；停用、未配置或资料不完整的任务进入“待补资料”。
- 工序未排定时，后续工序不会绕过它继续排程。

## 默认生产日历

初始化脚本建立“金米龙生产日历”，时区为 `Asia/Shanghai`：

| 作息 | 日期范围 | 工作日 | 工作时段 |
| --- | --- | --- | --- |
| 夏季作息 | 05-01至09-30 | 周一至周五 | 08:00-12:00、13:30-17:30 |
| 冬季作息 | 10-01至次年04-30 | 周一至周五 | 08:00-12:00、13:00-17:00 |

“系统配置 → 生产排程 → 生产日历”可修改作息名称、日期范围、工作日、工作时段和人工特殊日期。工作时段格式为 `08:00-12:00,13:00-17:00`。

中国法定节假日和调休使用 Python 包 `chinesecalendar` 明确导入。导入数据复制进本地例外表，运行试排时不访问公网；人工特殊日期优先保留，不被再次导入覆盖。当前已导入2026年25条与普通周历不同的节假日/调休记录。

## 默认排程策略

| 策略 | 规则顺序 |
| --- | --- |
| 交期优先（默认） | 按计划完工时间排序。同交期时，按当前设备占用顺排得到的交期余量从小到大排列，再按工单号和行号排序。 |
| 效率优先 | 比较整条工单剩余路线能填入现有设备空档的加工时长比例，比例高的优先；再比较剩余占机时间，短的优先。如果会让争用同一设备且原可按期的工单失去可行时段，先排受影响的工单。 |

在“系统配置 → 生产排程 → 排程策略”设置默认策略，在生产看板的工序进度中选择策略和方向。已开工工序先预留剩余加工时间，已完工工序显示实际时间。每个工单行按整道工序交接，剩余路线试排失败时释放临时时段。同一设备允许跨非工作时间接续，两个工作片段间不能插入别的工单。

- 顺排从现在、计划开工和上一道交割结束中适用的最晚时刻开始，逐道寻找最早可用时段。
- 逆排从计划完工倒推，逐道寻找最晚可用时段，并扣除与下道的交割时间。ERP 仅有日期时以对应工作日最后一个班次结束为截止，休息日取之前最近班次。无法在交期内逆排或没有计划完工日期时，待其他工单逆排后再顺排补排。试排以未来一年内的生产日历为范围。
- “工序交割”可维护上道工序、下道工序、分钟、启用状态和可选的路线版本。路线专用规则优先于通用规则；两者均缺失时按0分钟试算，并在任务详情提示。交割按生产日历的工作分钟计时，不占设备加工时段，单独显示交割和等待。设备档案中的换型准备时间仍为独立字段。

## 数据表

| 表 | 用途 |
| --- | --- |
| `mo_work_calendar_yx` | 生产日历主表、默认状态和修订号 |
| `mo_work_calendar_period_yx` | 夏季、冬季等循环作息及月日范围 |
| `mo_work_calendar_week_yx` | 每个作息下周一至周日的工作时段 |
| `mo_work_calendar_exception_yx` | 法定节假日、调休、加班、停产等指定日期覆盖 |
| `mo_schedule_policy_yx` | 排程策略主表 |
| `mo_schedule_policy_rule_yx` | 每套策略的规则顺序和启停状态 |
| `mo_schedule_handover_yx` | 有方向的工序交割时间，`route_id=0` 为通用规则 |

结构由 `webapi/production_scheduling.sql` 定义，只能明确运行初始化脚本，不随WebAPI启动自动建表：

```powershell
cd jml_admin/webapi
python init_production_scheduling.py --holiday-year 2026
python init_admin_permissions.py
```

后续年度在管理页面点击“导入年度节假日”，或者显式运行脚本。`chinesecalendar`未支持目标年份时应停止导入，不能自行猜测国务院安排。

现有数据库使用 `python init_production_scheduling.py --upgrade-strategies` 增量初始化工序交割表和效率优先策略，保留已有日历及历史策略记录。

## 接口和权限

- `GET /api/mo/dashboard/schedule-preview`：`admin` 只读试排，接受 `direction=forward` 或 `direction=backward`。
- `GET /api/admin/production-scheduling`：读取日历和策略。
- `POST /api/admin/production-scheduling/calendar/save`：保存生产日历。
- `POST /api/admin/production-scheduling/calendar/import-holidays`：导入指定年度中国节假日和调休。
- `POST /api/admin/production-scheduling/policy/save`：保存排程策略。
- `POST /api/admin/production-scheduling/handover/save`：新增或编辑工序交割规则。
- 权限：`production-scheduling.view/manage`；页面开关：`production-scheduling`。

配置保存使用修订号防止覆盖他人刚完成的修改，并写后台审计。页面停用、角色权限和平台只读上限继续生效。
