## 范围

后台账号与角色控制 jml_admin 的菜单、页面、按钮和 API。工站权限是另一套现场操作配置：后台保存线长、扫码员工、豁免人员、限时代理和总开关，报工服务按当前配置限制现场操作及报工查看范围；不以后台角色代替员工绑定，也不改变接收、完工的数量和拍照规则。

账号与开工／返工人员独立管理。本地账号继续使用原密码和 Flask Session；域账号继续由统一平台认证，不在前端保存 JWT。

## 首次启用

先备份现有生产管理数据库。在原 webapi Python 环境、原数据库环境变量下，从 jml_admin 目录执行：

```powershell
cd webapi
python init_admin_permissions.py
```

然后由部署人员构建前端并重启服务。初始化脚本不会随应用启动自动执行。

脚本创建 `mo_admin_role_yx`、`mo_admin_account_yx`、`mo_admin_account_role_yx`、`mo_config_approval_yx`、`mo_admin_page_setting_yx` 五张管理后台专用表，并迁移原 `mo_admin_user_yx` 的账号：

- 原 admin 账号分配系统管理员，原查看账号分配只读查看。
- 不修改旧密码，不修改 ERP、小程序、报工人员或工站数据。
- 可重复执行；保留账号角色分配关系，按当前权限集合迁移已有角色、补齐系统管理员权限，并升级审批所需字段。执行前仍须备份。
- 需要已有 `mo_admin_user_yx` 和 `mo_admin_audit_log_yx` 表，并至少保留一个启用的本地管理员。
- MySQL 建表会隐式提交；初始化中途失败可检查原因后重跑，不需要删除已建表。
- 权限表未初始化或数据库故障时，业务接口返回 503，不会退回旧管理员权限绕过检查。`/healthz` 仍可匿名访问。

报表邮件另使用SMTP密码；密码不通过读取接口返回，数据库只保存加密密文，实际初始值只放在部署环境文件中。

## 管理员怎么使用

1. 进入“系统配置 → 角色权限”，使用已有模板或新增角色，勾选页面和操作权限。
2. 进入“系统配置 → 后台账号”，新增本地账号或编辑已有账号，分配一个或多个角色。
3. 停用人员时关闭“账号启用”；不删除历史账号和操作记录。重新启用后，本地账号需要重新登录。
4. 本地账号忘记密码，使用“重置密码”；域账号密码在统一平台处理。重置会立即使旧会话失效。

默认模板：系统管理员、生产管理、工艺维护、单据打印、只读查看。除系统管理员外可编辑模板。账号管理和角色管理的“管理”权限含授权能力，只交给可信管理员。

系统管理员角色不可修改或停用。不能停用自己，不能移除最后一个启用的本地系统管理员。

## 授权规则

- 未授权默认拒绝，后台 API 每次重新读取账号状态和权限；角色停用或取消权限在后续请求生效。其他已打开页面的菜单需要刷新，但旧按钮无法绕过 API。
- 多角色权限取并集；授予操作权限时自动包含对应查看权限。
- 工序、工站、报工类别和工艺路线按“申请新增、申请编辑、申请状态调整、审批”分开授权；路线另有版本恢复申请权限。
- 2026-11-04工艺路线多版本并行后，原 `route.restore` 权限显示为“申请设为默认版本”，继续使用 `restore` 审批动作，已有授权无需迁移。新版本的 `set_default` 选择随 `route.edit` 提交，由 `route.approve` 审批后生效；未授权不能直接修改默认映射。
- 申请人在“审批中心”查看自己的申请。审批人只看到自己拥有审批权限的功能；申请人本人同时拥有该功能审批权限时，也可以审批自己的申请。
- 待审批的新增申请会显示在对应管理列表中，状态为“待审批”；该数据尚未写入正式配置，不会进入工序、工站、类别或路线的业务选择项。
- 申请人可以在对应管理列表修改自己的待审批新增或编辑申请。保存时服务端会重新检查审批状态和申请版本；已通过的申请不能修改，审批人也不能用旧页面审批修改前的内容。
- 被驳回的新增或编辑申请会在对应管理列表显示“已驳回”。申请人可点击“修改并重新提交”；重提后清除上次审批信息，状态回到待审批，已通过的申请不能重提。
- “审批中心”菜单角标合并显示“待我审批”和“我的未读审批结果”数量。进入“我的申请”后，已通过或已驳回结果标记为已读。
- 审批通过时才修改正式配置，并与审批记录、操作日志在同一事务中提交。如申请后正式数据已变化，则不允许直接通过，需重新申请。
- 不提供上述配置的删除功能和删除权限；历史直改、删除接口保留兼容路由，但服务端统一拒绝。
- 工序、工站、类别、路线等共享查询按调用页面权限任一满足放行；操作日志和权限管理不是通用查询接口。
- 单据查询和系统打印独立授权。打印前必须完成服务端授权，再写入原预览内容；保留委外领料单双联和签字页脚。不承诺阻止用户对已经可见的内容截图或使用浏览器自带打印。
- 未审核、已关闭订单的查询规则不变，不新增 ERP 审核限制。
- 完工记录中的二维码仍属于查看；未实现导出或打印的页面不增加空权限。生产现场看板页面和只读主接口允许未登录访问，原 `dashboard.view` 权限保留兼容但不再作为该公开页面的访问门槛；其他看板、报表和后台接口仍需登录及相应权限。生产看板已有Excel导出，具体范围见管理后台交接。
- 工站权限分为“查看”和“管理（含授权）”；工站人员和代理仍按角色权限维护。全局总开关、小程序报表开放范围及工站豁免人员名单仅用户名为 `admin` 的后台账号可查看和修改，其他账号即使拥有工站权限管理权限也不会收到这些全局配置。保存名单不自动切换开关。报工后端每次请求重新检查当前配置，取消授权或调整报表范围后下次请求即生效。
- 页面开关是全局可用状态，优先于角色权限。页面停用后所有账号都不显示菜单、不能直接进入，相关独占接口也会拒绝访问；重新启用后继续按原角色权限判断。“页面开关”自身固定启用，避免无法恢复。
- “需求计划 → 需求计算”使用独立 `demand-calculation.view` 查看权限和 `demand-calculation` 页面开关。销售订单查询和即时计算接口都是只读GET，不保存结果或写回ERP，因此当前不增加维护权限。
- “报表 → 末工序入库对账”使用独立 `receipt-comparison.view` 查看权限和 `receipt-comparison` 页面开关。升级执行 `init_admin_permissions.py` 时，原来具有 `reports.view` 的角色自动继承该权限；此后可在角色权限中单独调整，不与原生产报表绑定。
- “数据看板 → 生产报表2”使用独立 `reports2.view` 查看权限和 `reports2` 页面开关。升级执行 `init_admin_permissions.py` 时，原来具有 `reports.view` 的角色自动继承一次，之后两份生产报表可分别授权。角色权限按导航分组折叠显示。
- “报表 → 工单工序报告”使用独立 `workorder-process-report.view` 查看权限和 `workorder-process-report` 页面开关。升级时同样让原 `reports.view` 角色继承，后续可独立授权或停用。
- “生产管理 → 工序完工报表打印”使用独立 `completion-flow-report.view/print` 权限和 `completion-flow-report` 页面开关。查看权限可查询末工序已完成的工单行，打印按钮在服务端再次校验打印权限；升级执行 `init_admin_permissions.py` 时，原有生产标签查看、打印权限分别平滑继承对应的新权限。“生产管理”一级菜单在生产标签或该报表任一页面可用时显示。
- “系统配置 → 基础配置”使用独立 `basic-settings.view/manage` 权限和同名页面开关，当前“通信服务 → 邮件服务”维护全局SMTP，“业务通知 → 审批邮件”维护审批即时/每周规则并允许手动发送；默认只给系统管理员。页面只展示分组摘要卡，点击“配置”后在右侧抽屉维护；后续新增基础配置也按卡片扩展，不在主页全部摊开。
- “系统配置 → 报表发送”使用独立 `report-email-settings.view/manage` 权限和同名页面开关，只维护各报表发送任务；管理权限可修改任务并手动发送。定时任务仍受每张报表自己的发送开关控制。
- “系统配置 → 生产排程”使用 `production-scheduling.view/manage` 权限和同名页面开关。查看权限可读取日历、排程策略和工序交割规则，管理权限可维护这些配置。生产看板的工序进度试排只允许 `admin`。

## 报表发送配置

在 `webapi` 目录明确执行 `python init_report_email_settings.py`，创建 `mo_report_email_setting_yx`、`mo_report_delivery_setting_yx`、`mo_approval_email_setting_yx` 和 `mo_approval_email_delivery_yx`，已有配置不会被覆盖。初始SMTP可从被忽略的 `.env.smtp`、`.env.admin` 或 `.env` 读取；样例只放空值，不能把实际密码写入文档或前端。再执行 `python init_admin_permissions.py` 为系统管理员补齐页面权限。

SMTP全局维护一份，入口为“基础配置 → 通信服务 → 邮件服务”；每张报表独立维护收件人、抄送人、密送人、主题、正文、开关及手动/定时方式。定时支持每天、每周、每月，月度日期限制1至28日；接口按已保存规则返回下次发送时间，该时间为运行时计算结果，不另存数据表。保存SMTP和报表规则均写后台审计，但审计内容不含密码。手动发送前页面再次确认；关闭报表开关后手动和定时发送都不执行。“测试连接”只登录服务器后退出，不发送邮件；邮件服务读取、保存和测试分别要求 `basic-settings.view/manage`，报表任务读取、保存和发送仍要求 `report-email-settings.view/manage`。

审批邮件同样使用 `basic-settings.view/manage`：查看配置需要 `view`，保存配置及“发送最近审批”“发送每周清单”需要 `manage`。自动即时发送与每周发送分别有独立开关；手动按钮不依赖自动开关。审批邮件复用全局SMTP，不保存第二份SMTP密码。

2026-10-26已按用户要求在本地执行邮件配置与权限初始化：系统管理员获得查看、管理权限，生产现场看板、末工序入库对账和工单工序报告三张报表规则默认关闭；SMTP SSL登录验证通过，未发送测试邮件。

## 工站人员配置

升级时先备份数据库，在 `webapi` 目录执行 `python init_station_permissions.py`。脚本创建 `mo_station_staff_config_yx` 工站配置、`mo_station_staff_exemption_yx` 豁免名单、`mo_station_staff_proxy_yx` 限时代理表，并为原系统管理员补上配置管理权限；不覆盖已有名单。单纯重启不会建表。新安装先初始化后台权限，再执行本脚本。

总开关表另由 `webapi/station_access_settings.sql` 初始化，新增默认关闭、报表范围默认仅豁免人员。既有数据库执行 `python init_station_report_access_mode.py` 增加报表范围字段，不覆盖总开关或人员配置。开启前还需要报工侧 `mo_station_receive_binding_yx` 等既有业务依赖，不能把人员初始化脚本当作全库安装脚本。后台与报工服务必须连接同一套业务MySQL库；SQL和初始化只在部署人员明确执行时运行。

如需填入本次提供的人员对照，执行 `python init_station_permissions.py --seed-reference`。仅姓名精确且唯一匹配的在用 `jml_staff` 员工会填入；找不到或重名的人员跳过，已有工站配置（包括手工清空的配置）不会被覆盖。初始化日志明确标记为脚本操作，不伪装为员工提交。后来新增的人员由管理员在页面补选，不自动按姓名绑定。

进入“系统配置 → 工站权限”，搜索工站或人员，点击“配置人员”，选择一位线长和多位扫码员工后保存。可留空；清空后保存仅解除配置，不删除人员或历史记录。新增人员后点击“刷新人员”，无需重新部署。

- 配置保存员工 `jml_staff.id`，姓名仅用于显示；钉钉开工、返工人员保持独立。
- 人员选项仅返回 ID、姓名、岗位、状态，不返回密码、手机、微信身份等字段。停用／已删除的已配人员会标记不可用，可移除。
- 一人可在多个工站，一站可有多位扫码员工。并发保存校验版本，防止覆盖其他管理员刚保存的配置。
- 保存与审计在同一事务。API 返回数据库当前 `enforcement_enabled`；开关独立通过 `POST /api/admin/station-permissions/settings/save` 保存，携带 `enabled` 和 `revision`，不与人员保存混用。报工API读取同一套配置，不能在小程序另设本地开关。

### 工站豁免人员

在同一页面上方点击“设置豁免人员”，从 `jml_staff` 选择员工，点击“保存名单”。支持多选和按姓名搜索，无需逐站重复绑定。移除后保存即取消豁免；清空名单不会改变任何工站原有的线长和扫码员工。

- 豁免范围仅为所有工站的人员绑定限制，不授予后台菜单或管理权限，不绕过有效登录、员工启用状态、数量、照片等业务规则。
- 是否执行限制取决于后台当前总开关。没有默认豁免用户，也不按管理员角色或硬编码用户名自动加入。
- 小程序报表沿用报工权限范围，不另设人员名单；“报表开放范围”可选择“仅豁免人员”“工站授权人员”或“全部有效员工”，默认仅豁免人员，因此普通员工操作手册不包含报表操作。保存后小程序入口按后端结果动态变化，无需重新上传或重启服务；实际可查看数据仍按工站权限过滤。旧库首次使用前明确执行 `python init_station_report_access_mode.py` 增加设置字段，脚本默认保留“仅豁免人员”，不自动扩大权限。
- 2026-10-27本地业务库已执行上述报表范围迁移并重启本地管理后台，当前数据库值为 `exempt`。远程PythonAPI及小程序仍需按发布流程更新一次，之后后台切换范围无需再次上传小程序。
- “工站权限—查看”可以查看名单；“工站权限—管理（含授权）”才可修改。后端每次保存校验权限、员工状态和配置版本，记录真实操作人的修改审计。
- 新增员工后在编辑窗口点击“刷新人员”。已停用或删除的名单成员显示不可用，可点击“移除不可用人员”后保存，其他已选人员保持不变。
- 接口：`GET /api/admin/station-permissions/exemptions`，`POST /api/admin/station-permissions/exemptions/save`；保存仅接收 `staff_ids` 与 `revision`。

### 限时代理

工站“配置代理”可以增加指定生效和到期时间的操作人员；与负责人、扫码人员权限并行，不替换原绑定。报工服务实时校验有效期；到期清理任务负责移除过期配置并保留审计，清理任务停止也不能延长授权。配置和部署细节见[工站代理人](工站代理人.md)。

## 设备档案与标准产能（已在本地启用）

入口“工序配置 → 设备管理”，页面开关为 `equipment`。档案权限为 `equipment.view/add/edit/approve`；产能权限为 `equipment-capacity.view/edit/approve`。产能授权自动包含设备查看，维护权限包含本模块查看及 `approval.mine`；设备查看不自动授予产能维护或审批。两个模块共用设备页面开关，审批中心入口也纳入新的审批权限。

档案新增、编辑（含编号、名称、设备启停、换机）、标准新增、编辑和启停通过既有审批中心，模块名为 `equipment`、`equipment-capacity`。待审与驳回不影响正式数据，申请人与版本校验沿用原规则；正式写入、修订记录、审批与后台审计同事务。设备页面停用时，旧审批页面也不能通过设备变更。设备档案使用独立主表，不读取或写入原 `jml_device`，不改维修流程。

## 统一平台账号

使用认证来源、issuer 和稳定 subject 区分身份，不按姓名把域账号与本地账号合并。认证成功后首次进入会登记为后台账号：

- `production-view` 默认只读查看，且平台只读是上限，后台角色不能为其开启写操作（包括系统打印）。
- `production-admin` 默认生产管理，可由本地系统管理员分配更细的后台角色。
- `suite-admin` 在账号启用时拥有全部后台权限；后台角色不能缩小它在平台定义的超级管理员权限。要取消超级管理员身份须在统一平台调整，或者在本后台停用账号。
- 没有生产相关平台角色仍返回 403。
- 域账号显示名、实际审计操作人来自本次认证的真实身份，密码不在本系统管理。退出只返回统一门户，不退出其他应用。

账号页面中尚未出现的域用户，先通过统一平台进入一次即可登记。没有任何有效后台权限的账号进入无权限页，可以退出或返回获授权页面。

## 审计与验证

账号、角色和密码重置的成功记录与变更在同一事务提交，审计失败则回滚变更。失败／越权尝试使用白名单字段记录，不记录密码、密码 Hash、完整 JWT 或代理密钥。
