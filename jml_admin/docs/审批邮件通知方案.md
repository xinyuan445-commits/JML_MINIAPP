# 审批邮件通知方案

> 状态：第一版已于2026-11-02在本地实施并初始化。默认收件人为 `yuanxin@goldenchameleon.cn`，自动即时发送和每周发送开关均保持关闭。

## 目标

1. 每一张配置审批通过并正式生效后，立即将该审批内容单独发送到指定的 `goldenf...` 邮箱。
2. 不发送每日变更清单。
3. 每周发送一份从现有审批中心最早的已通过记录到发送时点的全部变更清单。
4. 每周清单按审批时间倒序排列，并对上一个自然周的新增或修改记录整行着色突出。

## 即时邮件

- 默认只发送已通过且已正式生效的审批；驳回申请默认不发送。
- 一张审批单对应一封邮件。批量通过多张审批单时，仍分别生成邮件，不合并成一封。
- 邮件正文显示审批单号、资料类型、操作类型、对象编码与名称、申请人、审批人、变更前后内容、审批意见及生效时间。
- 工艺路线步骤按序号逐行对照“修改前工序/工站、修改后工序/工站、结果”，结果区分保留、调整、新增和删除；非保留步骤使用浅黄色突出，不显示原始ID或JSON。
- 审批与正式资料仍在同一数据库事务内生效，同一事务只写入邮件待发任务，不在审批请求内同步连接SMTP。
- SMTP失败不回滚审批；后台任务自动重试并保存失败原因。审批单ID作为即时邮件唯一键，避免重复发送。

## 每周全量清单

- 建议每周一08:10发送。“上一周”固定按北京时间上一个自然周的周一00:00至周日23:59:59计算。
- 附件为一份 **全部审批变更 All List**，范围从第一条已通过审批到本次发送时间。
- 数据按“审批时间倒序、审批ID倒序”排列，最新记录放在最上面。
- 上一个自然周内审批通过的记录使用浅黄色 `#FFF2CC` 整行标记，用于快速识别本期新增或改动。
- Excel表头沿用项目默认样式：浅蓝底 `#D9EAF7`、深蓝字 `#17365D`并加粗。
- Excel第一行显示从最早审批时间到本次生成时间的数据范围、审批单数量和颜色图例；第二行为筛选表头，第三行开始显示审批明细。
- Excel中每个普通字段或工艺步骤独占一行，并增加“变更类型”列，不把多个字段用换行堆在同一个单元格；同一审批单的基础信息在各变更行重复，便于筛选和导出核对。
- Excel变更区域使用固定颜色强调：新增为绿色、修改为蓝色、步骤调整为橙色、删除为红色、保留为灰色；删除项的修改前内容增加删除线。上一自然周仍在其余基础信息列保留浅黄色底色，两层标记不会互相覆盖。
- 同一审批单有多条变更时，审批时间、审批单号、资料类型、操作类型、对象、申请人与审批信息纵向合并为一个分组；只有中间的变更明细保持逐行显示，并用蓝灰色上下边界区分审批组。
- 早期审批若修改后快照只保存对象ID、无法还原具体字段，不再显示含糊的“基础信息已更新”，统一标记为“历史审批明细 / 未保存具体变更内容 / 历史明细缺失”，使用浅橙色提醒；“历史明细缺失”和“上一周”不放入顶部颜色图例。
- 即使上一周没有变更，仍按周发送全部清单；邮件正文明确标注“上一周无新增或修改”，附件中没有黄色记录。
- 周期键作为每周邮件唯一键，定时轮询或服务重启不会重复发送。

清单字段至少包含：审批单号、资料类型、操作类型、对象编码、对象名称、修改前、修改后、申请人/时间、审批人/时间和审批意见。

## 配置与数据

- 入口放在“系统配置 → 基础配置 → 业务通知 → 审批邮件”，使用摘要卡和右侧抽屉，不在主页摊开。
- 可维护即时邮件开关、每周清单开关、每周发送时间、收件人、抄送人和密送人；不提供每日清单配置。
- 复用已有全局邮件服务，不新增第二套SMTP账号或密码。
- 审批变更数据来自 `mo_config_approval_yx`；另建审批邮件配置和发送任务/结果记录，不改写原审批记录。
- 页面提供“发送最近审批”和“发送每周清单”两个手动按钮。手动发送前会先保存当前收件人及规则，发送结果写入投递记录。
- 审批通过时只在同一事务写入待发记录；后台邮件任务每30秒处理待发记录。邮件失败不影响审批生效，失败任务最多尝试3次。
