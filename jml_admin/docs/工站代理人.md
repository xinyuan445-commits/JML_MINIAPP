# 工站代理人

## 使用

在“工站权限”中点击对应工站的“配置代理”，选择员工、生效时间和到期时间后保存。时间均为北京时间，可配置多人；新代理默认现在生效，到期时间必须填写。

有效期内，代理人与负责人、扫码员工的工站操作权限并行。代理授权只增加权限，不替换负责人，不改变原人员配置、豁免人员或工站权限开关。

可提前移除代理或修改有效期。到期后授权立即失效，清理任务每分钟自动删除到期配置，并保留审计日志。员工和历史报工记录不会删除；如果该员工同时是负责人、扫码员工或豁免人员，其原权限仍有效。到期后重新授权需重新添加。

配置沿用 `station-permissions.view/manage` 权限。原人员配置与代理配置分别保存，互不覆盖。多人编辑或打开弹窗期间授权到期时，保存会提示刷新，避免旧页面恢复已过期授权。

## 上线顺序

1. 在管理后台 WebAPI 使用的 DB2 数据库执行 `webapi/station_staff_proxies.sql`。这是新增独立表，不修改负责人配置表。也可在 `webapi` 目录运行 `python init_station_permissions.py`，不要添加 `--seed-reference`。
2. 更新报工后端 `JML_MINIAPP/pthonapi/services/mo_station_access.py` 并重启服务。必须先建表，否则开启权限控制时，报工权限查询会报错。新版 `/api/mo-v2` 和原 `/api/mo` 的相关报工入口共同执行有效期校验。
3. 更新管理后台前端及 WebAPI：`station_proxies.py`、`cleanup_station_proxies.py`、`admin_security_api.py`、`admin_permissions.py`、`app.py`、`init_station_permissions.py`、新增 SQL，以及工站权限前端文件和启动脚本。
4. 启动到期清理任务。正常 `npm start` 会自动启动并在后台退出时停止该任务。生产环境若单独运行 WebAPI/静态前端，须通过现有进程管理器托管 `python cleanup_station_proxies.py --loop`（工作目录为 `webapi`，使用与 WebAPI 相同的环境配置，开启自动重启）。

清理任务不可用时，到期授权仍被报工后端拒绝，列表不再显示；数据库中的过期配置会在任务恢复后移除。单次清理可运行 `python cleanup_station_proxies.py`。清理与到期审计在同一事务内，失败不会留下无日志的删除。

上线后建议验证：新增代理可报工、未生效代理不能报工、到期代理不能报工且自动移除、负责人在代理到期后仍可报工。线上初始化及重启需要另行执行，本次代码测试未修改线上数据。
