# 完工质量报告单

更新：2026-10-27。

## 业务规则

- 按本次完工提交判断，不读取工序累计等级数量。
- 原完工照片与质量报告单是两组独立照片，不能互相代替。
- 本次A1、A2、C任一数量大于0时，原完工照片至少1张、最多5张，同时必须另拍质量报告单至少1张、最多2张。
- 本次全部为A时，原完工照片可选拍、最多5张，质量报告单不要求拍摄。
- 普通完工、追加接收完工、返工完工和组合完工执行相同规则。
- 组合完工中，正常任务和返工任务分别保存各自的原完工照片；质量报告单由整次提交共用1至2张，只写入本次含A1、A2或C的相应批次。

## 数据保存

正常及追加接收完工的原完工照片写入 `mo_execution_completion_yx.photo_url`，质量报告单写入 `mo_execution_completion_yx.quality_report_photo_urls`；返工完工分别写入 `mo_rework_completion_yx.photo_url` 和 `mo_rework_completion_yx.quality_report_photo_urls`。质量报告单字段为可空长文本，内容是JSON数组。执行记录上的 `complete_photo_url` 继续汇总原完工照片，历史照片不自动改称质量报告。

增量脚本：`JML_MINIAPP/sql/mo_quality_report_photos.sql`。后端更新前必须先执行字段升级；脚本不会自动随服务启动执行。

## 接口与页面

- 原完工照片继续使用 `complete_photo_url`，支持单图或逗号分隔、最多5张；质量报告单使用 `quality_report_photo_urls`、最多2张。PythonAPI暂时兼容旧小程序把 `complete_photo_url` 同时作为质量照片的请求。
- PythonAPI服务端分别校验两组照片的数量和等级条件，不能只依赖小程序校验。
- 小程序两组照片都只调用相机，均允许预览、删除；其他开工、接收等照片仍沿用原数量规则。
- 小程序完工详情和管理后台完工记录详情均按完工批次显示质量报告。
- 新批次显示“质量报告单”，旧 `photo_url` 仅显示为“原完工照片”。现场操作日志继续记录本次提交的照片数组。
