# Mo 工序完工流转标签模板

本文档用于规划 `Mo` 现场管理模块中“每道工序完工后打印流转标签”的标签尺寸、字段内容和版式模板。

## 1. 使用场景

每个工单在某一道工序完工后，由操作员在小程序点击“完工”，系统生成一张标签，通过蓝牙标签打印机打印。

标签贴在完工产品、托盘、周转车或周转箱上，随产品进入下一道工序。下一道工序人员可以通过标签快速识别产品，也可以扫码进入小程序查看工单和工序记录。

## 2. 推荐标签规格

### 首选规格：60mm x 40mm

推荐作为第一版默认规格。

| 项目 | 建议 |
|---|---|
| 标签尺寸 | 60mm x 40mm |
| 打印方向 | 横向 |
| 打印类型 | 热敏不干胶标签 |
| 分辨率 | 203dpi 起步，300dpi 更清晰 |
| 适用场景 | 周转箱、托盘、小批量半成品流转 |
| 优点 | 蓝牙标签机常见规格，耗材容易买，信息量够用 |
| 缺点 | 产品名称太长时需要截断 |

### 备选规格：70mm x 50mm

如果后续发现产品名称、人员、数量说明较长，建议升级到此规格。

| 项目 | 建议 |
|---|---|
| 标签尺寸 | 70mm x 50mm |
| 打印方向 | 横向 |
| 适用场景 | 大件产品、周转托盘、需要更多文字信息 |
| 优点 | 字更大，二维码更大，车间可读性更好 |
| 缺点 | 标签纸成本略高，对打印机宽度有要求 |

### 不建议作为首版的规格

| 规格 | 不建议原因 |
|---|---|
| 40mm x 30mm | 内容太挤，二维码和中文字段难兼顾 |
| 50mm x 30mm | 可以打印，但车间快速识别不舒服 |
| 80mm x 60mm | 信息展示很好，但标签偏大，浪费耗材 |

## 3. 标签内容字段

### 必须打印字段

| 字段 | 示例 | 作用 |
|---|---|---|
| 工单号 | `MO20260708001` | 最核心追溯字段 |
| 行号 | `10` | 区分同一工单的不同行 |
| 产品编码 | `JML-A001` | 快速识别产品 |
| 产品名称 | `金米龙柜门板` | 现场人员识别 |
| 当前工序 | `压贴` | 表示刚完成哪一道工序 |
| 步骤 | `2/5` | 表示路线第几步 |
| 完工数量 | `合计 100` | 流转数量 |
| A级数量 | `A 96` | 良品数量 |
| C级数量 | `C 4` | 返工/不良数量 |
| 完工时间 | `07-08 16:25` | 流转时间 |
| 二维码 | 见下文 | 扫码追溯 |

### 建议打印字段

| 字段 | 示例 | 作用 |
|---|---|---|
| 工站 | `压贴1号机` | 定位生产设备/工位 |
| 下一工序 | `裁切` | 提醒流向 |
| 批次/箱号 | `1/3` | 多箱/多托流转时区分 |

### 不建议打印但可放入二维码的字段

| 字段 | 原因 |
|---|---|
| 操作人员 | 人员可通过扫码查看，标签上不占空间 |
| 完整人员列表 | 人多时标签太挤 |
| 备注/原因 | 内容长度不可控 |
| 完整日期年份 | 标签上可短显，完整值放二维码 |
| 所有子件清单 | 信息量太大，不适合流转标签 |

## 4. 二维码内容建议

二维码不要只放页面 URL，建议放结构化 JSON，方便以后扩展。

```json
{
  "type": "mo_process_label",
  "mo_code": "MO20260708001",
  "sort_seq": 10,
  "exec_id": 10235,
  "route_id": 3,
  "seq": 2,
  "print_time": "2026-07-08 16:25:30"
}
```

扫码后的处理建议：

1. 小程序扫码后识别 `type = mo_process_label`。
2. 根据 `exec_id` 打开 `Mo/ProcessMgmt/Detailed` 的完工记录详情。
3. 如果没有 `exec_id`，则用 `mo_code + sort_seq + seq` 查询。

## 5. 60mm x 40mm 标签模板

适合第一版上线。

```text
┌────────────────────────────────────┐
│ 工单 MO20260708001-10        [QR] │
│ 产品 JML-A001                     │
│ 金米龙柜门板                       │
│ 工序 压贴        步骤 2/5          │
│ ┌───────────┬──────┬──────┐       │
│ │ 合计 100  │ A 96 │ C 4  │       │
│ └───────────┴──────┴──────┘       │
│ 工站 压贴1号机    完工 07-08 16:25│
└────────────────────────────────────┘
```

### 版式尺寸建议

| 区域 | 尺寸/位置 | 内容 |
|---|---|---|
| 顶部标题区 | 高 7mm | 工单号 + 行号 |
| 右侧二维码 | 18mm x 18mm | 执行记录二维码 |
| 产品区 | 高 10mm | 产品编码、产品名称 |
| 工序区 | 高 7mm | 当前工序、步骤 |
| 数量区 | 高 10mm | 合计、A 级、C 级，使用粗边框突出 |
| 底部区 | 高 4mm | 工站、完工时间 |

### 字号建议

| 内容 | 字号建议 |
|---|---|
| 工单号 | 10-11pt，加粗 |
| 产品名称 | 9-10pt |
| 工序名称 | 10pt，加粗 |
| 数量合计 | 14-16pt，加粗，外框突出 |
| A级/C级数量 | 11-12pt，加粗，分格显示 |
| 时间/工站 | 7-8pt |
| 二维码 | 18mm x 18mm |

### 黑白标签的数量突出规则

因为标签是黑白打印，数量部分建议使用下面的处理方式：

| 处理方式 | 建议 | 原因 |
|---|---|---|
| 粗边框 | 数量区使用完整矩形边框 | 黑白打印最稳定，脏污后仍容易识别 |
| 大字号 | `合计` 使用全标签最大字号 | 现场流转最关注总数 |
| 分格 | 合计、A、C 分成 3 个格子 | 避免数字串在一起看错 |
| 反白 | 仅 C 级数量可选黑底白字 | C 级需要额外注意，但不要整块都反白 |
| 固定位置 | 数量区始终放在标签中下部 | 工人形成阅读习惯 |

推荐数量区样式：

```text
┌────────────┬───────┬───────┐
│  合计 100  │ A 96  │ C 4   │
└────────────┴───────┴───────┘
```

如果 C 级数量大于 0，可以打印成更醒目的黑底区域：

```text
┌────────────┬───────┬███████┐
│  合计 100  │ A 96  │ C 4   │
└────────────┴───────┴███████┘
```

实际打印时不建议用灰度底色，热敏打印机对灰度表现不稳定；要么纯白底黑字，要么纯黑底白字。

## 7. 字段映射建议

| 标签字段 | 前端/接口字段 | 数据来源 |
|---|---|---|
| 工单号 | `mo_code` / `MoCode_a` | U8 `momlist_yx`、`mo_execution_yx` |
| 行号 | `sort_seq` / `SortSeq_b` | U8 `momlist_yx`、`mo_execution_yx` |
| 产品编码 | `InvCode_b` | U8 `momlist_yx` |
| 产品名称 | `cInvName` | U8 `Inventory` |
| 当前工序 | `process_name` | `mo_execution_yx.process_name` |
| 工站 | `station_name` | `mo_execution_yx.station_name` |
| 步骤 | `seq / total_seq` | `mo_route_step_yx` |
| 合计数量 | `qty_done` | `mo_execution_yx.qty_done` |
| A级数量 | `qty_a` | `mo_execution_yx.qty_a` |
| C级数量 | `qty_c` | `mo_execution_yx.qty_c` |
| 完工时间 | `end_time` | `mo_execution_yx.end_time` |
| 下一工序 | `next_process_name` | `mo_route_step_yx` + `mo_process_yx` |

## 8. 打印触发建议

第一版建议在“完工成功”后弹出打印确认：

```text
完工成功

是否打印工序流转标签？

[暂不打印] [打印标签]
```

不建议一开始强制自动打印，原因是蓝牙连接不稳定时会影响完工主流程。更稳的做法是：

1. 完工接口先成功落库。
2. 返回 `exec_id` 和标签数据。
3. 前端弹出打印确认。
4. 打印失败时允许在历史记录中重新打印。

## 9. 重打标签建议

应在完工记录详情页提供“重打标签”按钮。

重打标签应使用原执行记录数据，不重新生成业务数据。可以额外记录打印日志，后续追溯谁在什么时候打印过。

建议后续增加打印日志表：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `exec_id` | 执行记录 ID |
| `mo_code` | 工单号 |
| `sort_seq` | 工单行号 |
| `seq` | 工序步骤 |
| `printer_name` | 打印机名称 |
| `print_status` | `success` / `failed` |
| `operator_id` | 打印人 |
| `operator_name` | 打印人姓名 |
| `print_time` | 打印时间 |
| `error_message` | 失败原因 |

## 10. 第一版建议结论

第一版推荐采用：

| 项目 | 建议 |
|---|---|
| 标签尺寸 | 60mm x 40mm |
| 标签方向 | 横向 |
| 核心内容 | 工单、产品、工序、大号数量、时间、二维码 |
| 二维码尺寸 | 18mm x 18mm |
| 打印触发 | 完工成功后手动确认打印 |
| 重打入口 | 完工历史详情页 |
| 二维码内容 | JSON，包含 `exec_id` |
