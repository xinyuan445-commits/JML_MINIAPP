# 报工数量规则实施说明（2026-10-27）

## 当前范围

本次只控制正常工序流转，返工接收与返工完工继续独立计算：

1. 本工站累计完工不得超过本工站累计接收。
2. 下一工站累计接收不得超过上一工序累计可流转完工数量。
3. 下一工站累计完工不得超过上一工序累计可流转完工数量，同时仍受本工站累计接收限制。

上一工序可流转完工数量按 A+A1+A2 计算，C级品不流入下一工序；旧记录没有等级数量时兼容使用原 `qty_out`。所有比较保留小数，误差容限为0.0001。

## 适用范围

规则只对ERP工单生产部门编码为 `041` 或以 `041` 开头的下级部门生效，不按工站区分。锯切及其他生产部门统一包含在此范围内，非生产部门不受限制。

第一道工序没有上一工序接收来源，因此统一允许直接完工；从第二道工序开始执行本工序接收上限和上一工序完工上限。该判断按工序顺序处理，不再维护“锯切线”等工站例外。

## 管理后台

“系统配置 → 报工数量规则”包含三个独立开关，页面固定显示适用范围为生产部门（041及下级），不再提供限制部门或例外工站配置。

配置表：

- `mo_quantity_rule_setting_yx`：单例规则开关，使用 `revision` 防止旧页面覆盖新配置。

早期本地版本建立过 `mo_quantity_rule_exception_yx`，当前代码已不再读取或维护该表；为避免破坏已有数据，本次不删除旧表。

权限为 `quantity-rules.view`、`quantity-rules.manage`，页面仍受后台页面开关控制。保存操作写入后台审计日志。

## 报工后端与小程序

PythonAPI在事务内锁定执行记录和交接记录后重新读取累计数量并硬校验，开启规则后不能用“填写超出原因”绕过。覆盖普通完工、继续完工、交接接收、追加接收、追加接收完工和正常任务与返工任务组合完工；组合完工只限制其中的正常任务。

小程序在完工、交接接收和追加接收弹窗中实时读取规则上下文，显示“本次最多可完工/接收”，输入超限时不提交。客户端提示只用于操作体验，最终以后端校验为准。

## 启用与兼容

- 2026-10-27已执行表和权限初始化，三个开关均保持关闭，因此当前已运行小程序和现有报工行为不受影响。
- 适用部门按ERP工单 `DeptCode` 判断，不依赖工艺路线是否维护部门；锯切和其他 `041` 下级生产部门无需逐项配置。
- PythonAPI在配置表尚未初始化时按全部关闭处理，便于先部署代码再安排启用；其他数据库错误不静默忽略。
- 当前没有作废接口、删除字段或清理历史数据。旧版小程序仍可调用原接口，但规则一旦开启，也会受到后端硬校验。

## 发布顺序

1. 先部署含硬校验的PythonAPI，保持三个开关关闭。
2. 上传并发布含最大数量提示的小程序，完成真机验证。
3. 在管理后台逐项开启规则。
4. 抽查小数、分批完工、多人并发、追加接收和组合完工。

在用户确认小程序上线前，不作废原接口、不删除旧的“超量填写原因”兼容字段和页面逻辑。
