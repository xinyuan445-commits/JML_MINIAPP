## 1. 范围与约束

- 在微信小程序“现场管理”增加无工单任务管理，支持5S、盘点、设备保养、问题整改、培训、其他临时工作。
- 不要求ERP工单、产品、料号、生产数量或工艺路线；任务允许不关联工站。
- 管理后台“生产管理 → 工站每日任务”支持安排及核对，明确区分工单与无工单任务。
- 只明确个人责任与完成情况，不做个人工作量比较或考核。
- 保留工作区全部既有改动与未跟踪文件，不改变现有工单报工和维修流程。
- 当前允许阶段1—4本地代码、文档及隔离测试；不操作真实业务数据库，不执行真实初始化、清理、重启、部署、上传、提交或推送。

## 3. 已确认：人员与任务结构

本节更新后，文档中的“当前负责线长／负责人”包含以豁免资格发布并负责该任务的人员；不因此改变其原工站岗位。

- 普通线长可以发布任务，指派自己以及自己负责工站中配置的扫码人员；本人无需另行配置为扫码人员。
- 豁免人员可以发布任务，指派工站权限表中配置的全部线长和扫码人员，按员工ID合并去重；不扩大到全体员工名册。豁免人员本人只有同时属于上述配置人员时才进入执行候选。
- 豁免人员在小程序「我管理的」可查看和操作所有已发布无工单任务，可修改、换人、取消、代管授权、交接，也可以逐人代接收、开工、暂停、提交、处理职责反馈和修正用时。可以核对自己或自己代提交的记录，并确认分工完成。他人的未发布草稿仍仅本人可见。
- 代操作归属到实际执行员工的分工、计时和完成记录，操作历史同时记录代办人及代办对象。仍按执行员工校验同时只能有一条计时。豁免撤销后按当前有效个人和任务授权处理。
- 普通线长负责多个工站时合并扫码人员并去重，再加入本人；不关联工站的任务也使用发布人相同的指派范围。候选员工账号必须有效。
- 不推断额外员工名单，不为派任务而扩大原有扫码报工权限。
- 总任务下面有多条分工，每条分工可以指派一个或多个人。
- 多人分工须在执行前明确每个人负责什么；单人分工可沿用分工内容，减少重复填写。

### 已确认：草稿与发布

- 小程序由有效线长或豁免人员直接发布，不增加发布前审批。后台发布时，任务负责人只可选未列入豁免名单的有效线长；同时具有线长和豁免资格的人员也排除，保存和正式发布分别校验。
- 发布人保存的任务草稿不向被指派员工开放，不允许接收，也不进入后台待安排。
- 发布成功后，被指派员工可查看、接收；任务自动进入后台可安排候选范围。
- 发布不自动创建每日安排单，不按计划日期自动生成任何个人日安排。
- 后台安排仍是计划，不作为任务发布审批或员工开工前提；完成后的线长核对独立保留。

### 已确认：线长交接、代管及撤权

- 原发布人永久保留，另记录当前负责线长。无工站任务当前视图按当前负责线长分组；临时代管不改变分组，已锁定历史分组不改。
- 短期离岗明确指定具体任务代管人及有效期；调岗、离职正式交接任务，记录前后负责人、操作人、原因与时间。
- 原线长有权时可发起交接；离岗或撤权后由具备专门任务交接权限的后台人员处理。原发布人身份本身不保留已撤销的管理权限。
- 现有工站代理不自动获得无工单发布或任务管理权。豁免人员的小程序操作范围见本节人员规则；其他人员的任务代管须明确授权，仅因被指定为代管人不获得发布新任务的资格。
- 代理到期／撤销立即失效，既有合法操作记录保留；不得把代理操作记成原线长操作。
- 暂无有效负责人时任务提示待交接；员工账号及原指派仍有效的，可继续执行和提交，核对及时间修正等待有权人员处理。
- 仅更换管理人不改变员工职责，不自动暂停计时或要求重新接收；实际职责变化另按第7节处理。
- 接管权针对已交接任务及其历史记录，新增／换人仍按当前管理人有效指派范围；不能从接管历史推导出任意派人权。
- 已完成任务后续发生时间修正，由当前有权负责人或明确接管人处理，不依赖离岗原线长。

### 已确认：负责人本人执行时另选核对人

- 非豁免的任务负责人被指派执行时，每个总任务另选一名“本人执行核对人”；同一时刻最多一名。豁免负责人可在小程序自行核对本人执行记录。本人执行也逐步接收、开工、暂停或提交。
- 候选为工站权限中其他有效线长或有效豁免人员，排除本任务执行人员；普通员工及被指派的其他线长，仍由当前负责人与其合法授权人核对。
- 发布时包含负责人本人指派，必须同时选好核对人；已发布任务追加本人执行，也必须先落实核对人。尚未选好可保留草稿，不允许带缺失核对人的本人指派直接发布。
- 指定核对人的授权范围含负责人本人的完成提交、补材料、补做、时间修正、职责问题反馈，以及含负责人本人执行的分工整体完成确认；逐人核对后仍需确认分工整体完成。普通线长、员工和代管人员继续执行本人核对限制，小程序豁免权限见本节人员规则。
- 特殊核对人只查看处理这些事项所必需的任务要求、记录及结果，不因此获得整项任务调整、换人、取消、代管授权或正式交接权，不因此获得无关人员全部私有记录。
- 核对人失效或需要参与任务执行时，先更换核对人，保留原核对结论和更换原因；跨任务时间修正仍须同一处理人对所有受影响事项均有时间核对权。
- “本人执行核对人”是独立且受限的任务职责，不把任务负责人改成核对人，不改变无工站当前负责人分组，不改已冻结安排／结果。

### 已确认：与代管、交接衔接

用户已确认以下代管与交接方向；本轮实现边界和验证结果见文末补充。

1. **普通代管不能绕过特殊核对。** 有整任务成果／时间核对权的代管人，不自动替代已指定的本人执行核对人；如需接手，显式变更该核对人。代管人若自己参与执行，自己的提交同样不能自己核对，交由另一个符合该事项权限的人。
2. **一人多种授权分别记录。** 同一人可以兼任不涉及执行的普通代管和本人执行核对人，但各项范围、有效期、撤销独立；撤销其中一个身份不隐式删除另一个。界面应展示仍有效的授权来源，不能通过角色权限简单取并集绕过自核对、特殊核对限制。
3. **交接必须同时确认核对安排。** 正式交接继续默认撤销原普通代管；特殊核对人需在交接时明确保留或更换，不能自动继承、自动消失或照搬普通代管撤销规则。新负责人也被指派执行时，交接生效前选好符合条件的核对人；原负责人已做的工作、未处理提交、后续时间修正仍须有明确归属。
4. **核对对象跟随具体人员与历史指派，不仅跟随当前负责人字段。** 交接、换人或撤销指派不能把旧提交转记给新人，也不能让原特殊核对范围悄悄消失。维持每任务一名当前特殊核对人的简单模型，交接时明确其需承接的原／新负责人事项；已结束的授权与实际核对人照常留历史。
5. **更换权限与失效兜底。** 有权任务负责人可指定／更换特殊核对人并填写原因，普通代管不凭任务调整权自行转授此职责。负责人失效后，由具有专门任务交接权限的后台人员安排接管及核对人；后台交接权限本身仍不能代核对。外部配置导致核对人突然失效，提示待补核对人，拒绝失效人员核对，不删除已做记录或已提交内容。
6. **豁免负责人资格来源要补齐。** 新建／正式接管时记录实际依据的线长工站资格或豁免资格，不用“空工站”冒充有效线长。撤销豁免或其依赖的线长资格后，不因另一身份仍存在就静默保留旧任务管理权，应明确重新授权或交接。建议正式接管人允许有效线长或豁免人员，仍按接管人自己当前有效指派范围新增／换人。
7. **防止通过撤销执行记录成为核对人。** 核对候选除排除有效执行指派外，建议排除本任务已有实际执行／完成提交的人员；历史已做过的工作不因撤销指派消失。未接收且已撤销、无时段和工作记录的指派不算实际参与；已接收或有记录者继续排除。

## 5. 已确认：接收、开工、暂停及跨天

- 每人分别接收，接收仅认领本人责任，不代表开工。
- 每人自己点击开工、提交完成；同一员工同时只能有一条无工单分工计时，切换前先暂停。本次不跨模块拦截原工单报工或维修计时，避免改变既有流程。
- 开工开启计时段，暂停结束该段，继续时新建计时段；暂停期间不计用时。
- 下班未完可暂停，次日继续，不重建任务、不重新接收。
- 实际连续工作跨零点时继续计时，按日期拆分统计；不在零点自动暂停或完成。
- 不默认按生产日历扣午休或夜间。
- 个人累计用时为各段有效工作时间之和；总任务执行历时为最早开工到最后一次工作完成提交的时间跨度，包含等待与隔夜间隔。仅补材料的重提不延长执行历时，补做则按新工作提交更新；最终核对时间另记。
- 线长核对时间独立记录，核对等待不算个人用时；退回补做重新开工增加计时段。
- 漏暂停等按员工申请、线长确认的工作时段修正规则处理，详见本节时间修正部分。
- 暂停原因按配套默认设计使用简短必选项：休息、等待材料、等待配合、临时调配、其他；其他填写说明。线长调整等系统动作自动记录原因。

### 已确认：部分接收与职责反馈

- 本人接收后，职责明确且具备执行条件即可先开工，不要求同分工所有人员都接收；未接收人员须先接收再开工。
- 需要他人配合或前置工作、当前无法执行时，暂不开工；已开工则暂停并反馈，不因已接收而持续计工作时间。第一版不建立复杂的工序依赖。
- 接收前后均可向当前有权负责线长或明确代管人“反馈问题”，问题说明必填，照片／附件选填，保留反馈及回复记录；原发布人不因历史身份自动保留处理权。
- 反馈不自动取消指派，也不算完成。明确需要澄清后才能做的，只阻止受影响人员开工或继续；若正在计时，提交该阻塞反馈时结束当前计时段，并明确提示员工。
- 不受影响的人员可继续，不自动暂停整条分工或总任务。
- 线长解释原职责时，员工确认已明确后再接收或继续；线长修改职责、范围、标准时保留变更，受影响员工重新确认接收；换人、取消沿用相应规则。
- 线长处理后须由员工确认，再由员工自己点击开工或继续；线长回复、员工确认均不自动开始计时。

### 已确认：时间修正与跨日锁定

- 原始接收、点击开工、暂停、提交等操作时间不改写；员工申请修正实际工作时段，不直接填写累计小时数。
- 支持调整开始／结束时间、将连续时段拆分以扣除漏记休息、补充漏记时段，以及将误点且未实际工作的时段标为不计用时；原记录保留。
- 仍在计时的须先正常暂停或提交完成，再申请修正已结束时段。
- 员工只申请本人时间修正，原因必填、附件选填；展示原时段、修正时段、用时差额和影响日期。
- 线长确认后生效，退回须说明原因，员工修改后重提；待处理期间沿用原有效时间并标记待核对。
- 同一时段不重复提交待处理申请；再次修正保留完整历史。
- 不允许负时长、未来工作时段，不能与本人其他无工单分工的有效工作时段重叠；误记到其他任务时须核对两边，不重复累计。
- 修正独立于成果核对，不自动撤销完成结果或恢复开工；已完成、已取消任务也可修正历史时间，第一版暂不设申请天数期限。
- 未锁定日期在修正通过后重新计算；已锁定每日结果保持原值，附后续修正记录，展示原值、修正值和差额，不覆盖锁定快照。
- 小程序任务详情和个人累计用时使用已确认修正结果，并可追溯原始记录。
- 跨日按实际受影响日期核算，不将历史扣减计为申请或确认当天的负工时。例如昨16:00开工、实际17:00结束而今08:00才暂停，修正后有效用时1小时，按昨今两日分别处理影响。
- 历史打印／Excel原锁定结果不变，后续修正单列；具体默认格式见配套数据设计。

## 6. 已确认：提交、核对及退回

- 本人实际完成内容必填，照片／附件选填，异常或补充说明选填。
- 提交时结束本人计时，进入待核对；不能代表其他人完成。
- 线长逐人核对，通过可不填意见，退回必须说明原因及要求。
- 退回分“补充说明／材料”和“补做工作”：前者补充后重新提交，无需为修改说明开工；后者重新开工，补做后提交。
- 退回只影响指定人员，其他通过结果保留；原提交、退回、再次提交均留痕。
- 当前仍需履行职责的人员全部通过，且分工整体达到完成标准，才确认分工完成；已撤销／被替换的旧指派不永久阻挡完成，但历史待核对提交须明确处理。所有未取消分工完成后可完成总任务；全员撤销或全部分工取消不能自动视为完成。
- 核对最后一人时可以同时确认分工整体完成；整体仍有遗漏时明确交给谁补做。
- 此处为执行结果核对；第一版不设发布前审批，由有效线长或豁免人员直接发布。普通线长本人执行按第3节另选核对人。

## 7. 已确认方向：修改、换人及取消

### 修改

- 日期、截止时间、备注、附件可调整并留变更记录，员工端提示变更。
- 内容、标准、个人职责未接收时可调整；接收后变更说明原因，受影响员工重新确认接收。
- 已提交或通过的记录保留当时要求；新增要求通过新增分工或退回处理，不直接改写历史依据。
- 可新增分工或人员，新人员独立接收。
- 已完成总任务不重新打开追加工作，新增工作另建任务。

### 已确认：执行中变更职责的衔接

- 原职责、原接收及已执行记录保留，新职责需受影响员工确认接收后执行，不清空历史。
- 日期、备注、参考资料等未改变实际要求的调整，留记录并提示，不停止计时、不要求重新接收；实际改变内容、范围、标准或本人职责时，必须说明原因并展示差异。不能通过在备注中加入新要求绕过重新接收。
- 线长编辑未保存不影响员工；保存生效前展示受影响及正在计时人员，生效时只结束受影响人员当前计时段，记录为“职责变更暂停”。其他人员继续。
- 尚未接收人员接收最新职责；已接收未开工人员变为待重新接收；正在计时人员暂停并待重新接收；原已暂停人员保留暂停及已有用时，重新接收后才能继续。
- 重新接收展示原职责、新职责及变更原因；确认不自动计时，员工自己点击开工或继续，不清楚可继续反馈。
- 已提交待核对的记录按提交时职责和标准核对，不覆盖原要求；原工作未达标走退回补材料或补做，新增范围／提高标准另建分工，不以新标准否定原提交。
- 旧工作需补做且存在新增要求时分别记录；已通过结果保留，新增工作另建分工，不将已完成自动改为未完成。
- 旧页面不能按旧职责直接提交为新版本完成结果，应提示刷新确认。
- 总任务或分工公共标准变化须列明实际受影响范围，对要求改变的人员重新接收；不静默修改已提交或通过人员的历史依据。
- 后台已锁定安排及结果保留原内容，当前职责及变化从任务详情、变更记录查看。

### 换人

- 新人员仍受线长可指派范围限制。
- 未执行可撤销原指派，保留调整记录。
- 已部分执行须说明已做内容及剩余工作；旧人员的用时、反馈归旧人员，新人员接收剩余工作。
- 原人员计时中，换人生效结束该段，并明确记录为线长调整指派，不伪装成员工主动暂停。
- 已有待核对提交先处理，再交接剩余工作。

### 取消

- 支持撤销个人指派、取消分工、取消总任务；填写原因。
- 结束受影响计时，终止后续执行；保留已做、已提交及已通过记录。
- 待核对提交不因取消隐藏，线长仍需处理；已通过结果不改为取消。取消后允许补事实材料、核对和时间修正，不允许退回补做重新激活执行；不合格则记录未达标及取消原因结束历史待办，需要继续工作另建关联任务。
- 总任务取消后不显示为全部完成。
- 第一版暂不提供一键恢复取消任务，继续工作另建并关联原任务。
- 取消某天安排不等于取消任务，不能改写已锁定安排或结果快照。

## 8. 已确认方向：后台安排与日期衔接

- 第一版由一名 PMC 在后台统一安排。PMC 使用明确授予的全范围计划权限，将已发布的个人指派排到执行日期；小程序任务的发布和人员职责由任务负责人维护。页面操作见第14.5节。
- 使用现有独立安排单、拖拽、本地草稿统一保存、补充安排、跨日锁定机制。
- 工单与无工单任务明确区分，不用假“1件”兼容，不套用生产数量和等级核对。
- 有工站任务进入关联工站，无工站任务按当前负责线长分组，保留原发布人，不建虚拟工站；无工站区不被隐藏空工站开关一起隐藏。
- 最小安排单位为分工中的个人，卡片可按分工合并。
- 同一分工不同人员可安排不同日期，同一人员可安排多天。
- 未保存草稿不影响小程序；后台安排先定位为日期、顺序安排，不通过拖拽隐式换人或换线长。
- 原计划执行日期、截止时间由线长任务维护；个人日安排由后台维护；实际时间由执行形成。
- 后台安排不覆盖原计划；修改原计划不自动移动已保存日安排，提示核对；超期提示不自动延期。
- 改期与追加日期区分；锁定历史不改，新日期另安排。
- 接收针对个人职责，安排多天不重复接收；完成指职责完成，不要求每天提交完成。
- 后台安排仅为计划，无当天安排也允许开工，但必须能核对实际执行。
- 创建次日锁安排，执行次日锁结果；任务本身可继续流转，不回填或覆盖历史快照。

### 已确认：无工单待安排候选

- 只从已发布任务中选取，按总任务、分工分组并展开到个人职责；保留关联工站或无工站当前负责线长分组。
- 尚未接收、已接收、正在做、暂停、退回补做的个人任务均可安排；进入候选不表示已允许开工，接收与开工条件另行校验。
- 同一人员分工当天已有有效安排时不重复添加；其他日期有安排时显示日期，允许追加其他日期。
- 待线长核对、退回补材料的个人任务默认不进入工作安排候选，仍可查看核对记录。
- 已通过的个人任务及已取消指派不再新增安排，其他尚未完成的人员任务保留候选资格。
- 日期筛选使用分工计划日期；已开始但未完成的工作进入“现场待做”，不被原计划日期筛选挡住。待核对、补材料、通过或取消仍按上述候选规则处理。
- 后台拖拽只修改本地草稿，未保存不影响小程序日期；按配套默认设计，正式发布日安排才对员工生效，已保存未发布仍为服务器草稿。

## 9. 已确认方向：后台执行核对

- PMC 核对计划与执行是否对应；各任务负责人按任务的验收要求核对成果。负责人本人执行时，由已指定的核对人处理。后台按当前具体任务授权开放操作，页面见第14.6节。
- 分已安排任务、未安排执行，按分工＋人员＋执行日期匹配。
- 同分工部分人员安排、部分未安排分别归属，不因一人安排将全组算作已安排。
- 显示任务及分工、当前负责线长及原发布人、工站、个人职责、当天工作时段与用时、完成反馈及核对结果；锁定历史保持当时资料，不能用当前负责人覆盖历史。
- 无当天安排单也能按日期查询，不要求先建空单。
- 未安排执行可查详情及按截止规则补充安排，不强制为消除标记补单。
- 只暂存草稿不算已安排；补单保存并发布后重新归类，不复制实绩，保留安排创建与开工时间。已发布安排修改保存后生效。
- 在其他日期已有安排时提示，但实际提前开工不自动移动或取消未来安排。
- 安排已取消但有实际执行，单独提示，保留全部记录，不与从未安排混淆。
- 当日核对记录与当日实际工作区分，避免重复计时；昨天提交今天通过不改写昨天锁定结果。
- 后台查看／安排维护权不自动授予线长通过／退回权。
- 无工单未安排执行明确展示，不恢复此前隐藏的工单安排外生产入口。

## 11. 已确认：字段层级

原则：总任务描述共同目标，分工描述独立工作内容，个人层明确责任并记录执行；后台日安排作为另外一层日期记录。

### 总任务

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 总任务内容 | 必填 | 简短描述整体目标，列表可直接使用，不再另填重复标题 |
| 工作类别 | 必填 | 总任务默认类别，分工默认沿用，允许不同分工使用不同类别 |
| 总体完成标准 | 必填 | 线长判断整项任务完成的依据 |
| 计划执行日期 | 必填 | 默认当天，作为分工默认计划日期，不等同具体人员日安排 |
| 截止时间 | 选填 | 整体期限 |
| 原因／备注、参考附件 | 选填 | 共用背景和资料 |
| 本人执行核对人 | 负责人本人执行时必填 | 总任务层选择一名；仅负责第3节限定事项，不等同代管或负责人 |
| 任务编号、创建／发布人员及时间 | 自动 | 不重复手填 |

### 分工

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 分工内容 | 必填 | 明确对象、地点、范围；只有一条分工时可沿用总任务内容 |
| 分工完成标准 | 必须有有效值 | 默认沿用总体标准，不同要求单独填写，避免重复输入 |
| 工作类别 | 默认沿用，可调整 | 同一总任务可包含清扫、盘点等不同类别的分工 |
| 关联工站 | 选填 | 放分工层，同一总任务可有不同工站或无工站分工 |
| 指派人员 | 必填，一人或多人 | 按第3节：普通线长为本人＋所负责工站扫码人员，豁免人员为全部配置线长及扫码人员 |
| 计划执行日期 | 默认沿用总任务，可单独调整 | 与后台按个人日安排分开 |
| 截止时间 | 默认沿用，可设更早期限 | 超出总任务期限时须先调整整体期限 |
| 补充备注、参考附件 | 选填 | 只补充分工特有信息，共用资料仍可查看 |
| 分工编号、整体状态 | 自动 | 状态依赖执行与线长核对 |

### 个人指派及执行

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 人员 | 从指派名单带入 | 不重复输入姓名 |
| 本人负责内容 | 必须明确 | 单人默认沿用分工内容，多人逐人明确 |
| 完成标准 | 沿用分工 | 第一版不再强制增加一层个人标准，个人特殊要求写入负责内容 |
| 本人实际完成内容 | 提交时必填 | 建立时不填 |
| 完成附件、异常说明 | 提交时选填 | 建立时不填 |
| 接收、开工、暂停、提交时间及累计用时 | 系统记录 | 按实际动作形成 |
| 核对人、时间、结果及退回要求 | 核对时记录 | 通过意见选填，退回要求必填 |

### 后台每日安排（与上述三层分开）

关联分工和人员，记录具体执行日期、安排单、顺序、安排备注及取消记录；同一人员分工可有多个执行日期。具体字段及匹配规则后续讨论，不直接覆盖总任务或分工原计划。

- 历史保留不等于保留访问权限：历史详情、冻结结果、附件和导出均按当前权限过滤。员工仅查看本人记录及必要公共要求，不能读取同事完整成果、用时和附件。
- 代管有任务管理权不等于拥有线长的派人名单；新增／换人须有本人有效派人范围。核对本人完成或时间修正默认禁止，须由另一个明确有权人员处理。交接时旧代理默认撤销，需要保留则明确重授。
- 任务发布、每日安排发布、员工执行是独立状态。创建日锁定但未发布的服务器草稿保留，释放候选占用，让当天补充单能够正式安排；不通过删除草稿实现释放。
- 每日实绩唯一固定来源为无工单日期冻结结果，含有安排但零执行的任务；安排单只关联本单子集，不维护第二份可独立变化的无工单实绩。
- 截止前申请、截止后批准的修正，只附历史修正；补存须读取截止时有效版本，不直接用当前修正结果。历史原本无执行而后补记的，同样不冒充当日已存在的事实。
- 个人指派换人新建、撤销留痕，当前完成判定不把旧人员永远算作待做；取消后的历史核对不恢复执行，全员撤销不能自动判为完成。
- 要求版本与普通保存版本分开。总任务默认值建立时带入，发布后不动态传播；实质要求变化明确范围、重新接收，旧提交继续按旧要求核对。
- 首轮完成须有本人有效开工记录，漏记通过时间修正补齐；补材料无需新增计时，补做须有新工作记录。账号停用后未结束计时列异常，由有权人员明确处理，不假定实际停工时刻。
- 当前方案保持9张表，不增加通用审批／动态继承系统。数据库类型、附件访问条件、零点并发与权限边界需要后续实施验证，文档审查不代表功能已实现或测试通过。

## 14. 已确认：页面、入口、按钮及操作流程

### 14.1 小程序入口与页签

入口为“现场管理 → 无工单任务”，新增独立模块，不把原工单报工改成新流程。

| 页签 | 资格及内容 |
| --- | --- |
| 我的任务 | 被指派员工查看本人的待接收、待做、进行中、待核对及历史指派；线长本人被指派时也可见 |
| 我管理的 | 当前有权负责线长、明确代管人查看管理范围内总任务、分工和人员进度；已交接任务不继续作为原线长当前管理任务 |
| 待我处理 | 按实际权限展示完成提交、问题反馈、时间修正及待交接事项；提示待办不代表已获得处理权 |

### 14.2 建立、发布和修改

- “我管理的 → 新建任务”进入一个编辑页，分总任务、分工、指派人员三块；点击“添加分工”增加工作，多人逐人填写负责内容。
- 总任务／分工字段按第11节，默认带入减少重复填写；指派负责人本人时展示并要求选择本人执行核对人，确认清单一并显示。
- “保存草稿”仅保存任务草稿；“发布任务”先展示分工及人员确认清单，再发布。发布后员工可接收、后台可安排，不自动生成日期安排。
- 已发布任务使用“保存修改”；实质职责变化列出受影响及正在计时人员，按第7节暂停、重新接收。

### 14.3 员工任务详情与按钮

列表一张卡对应本人的一条个人指派，显示总任务、本人职责、计划／安排日期、状态。详情包含“我的职责”“日期安排”“工作时间”“完成与处理记录”，不返回同事的私有执行内容。

| 状态 | 主要操作 |
| --- | --- |
| 待接收 | 接收任务、反馈问题 |
| 已接收未开工 | 开工、反馈问题 |
| 正在做 | 暂停、提交完成、反馈问题 |
| 已暂停 | 继续工作、提交完成、反馈问题；提交仍须符合有效工作记录等校验 |
| 职责变更 | 查看变更并重新接收 |
| 问题已处理待本人确认 | 查看回复并确认，确认后自行开工／继续 |
| 待核对 | 查看提交记录 |
| 退回补材料 | 补充并提交，不新增计时 |
| 退回补做 | 开始补做 |
| 已完成／取消 | 查看历史，符合条件时申请时间修正；取消不恢复执行 |

- 提交完成只强制填写本人完成内容，附件选填；停止本人计时并进入待核对。
- 反馈问题和时间修正从任务详情进入，不再增加主页面。反馈含说明、附件和是否需处理后才能继续；修正选择时段，调整／补段／剔除并填写原因，显示前后差额及影响日期。
- 时间修正先正常结束仍在计时的时段；按钮隐藏不能代替后端权限及状态校验。

### 14.4 线长核对及管理

| 待办 | 核对内容 | 按钮 |
| --- | --- | --- |
| 完成提交 | 原职责、标准、本人反馈、附件、用时 | 确认通过、退回 |
| 问题反馈 | 问题及当前职责 | 回复处理、修改职责 |
| 时间修正 | 原／申请时段、差额、日期和原因 | 确认修正、退回申请 |

- 退回选择补材料／补做并填写要求；核对最后一人时可同时确认分工整体完成。取消后的提交执行第13节特殊规则，不显示可恢复执行的补做按钮。
- 总任务“更多操作”：修改任务、添加分工、调整人员、指定代管、交接任务、取消任务；只显示当前有权操作，代管不自动获得发布／转授权能力。

### 14.5 后台安排单及待安排区域

第一版以一个 PMC 统一排期为日常操作方式。页面沿用“生产管理 → 工站每日任务”。有全范围安排权限的 PMC 可在同一张安排单中同时安排工单和无工单任务。

| 页面位置 | 显示内容 |
| --- | --- |
| 安排单列表 | 执行日期、主单／补充单、发布及锁定状态。工单安排条数和无工单人员安排条数分别显示。保留新建、维护／查看和补充安排，增加“无工单执行查询”入口 |
| 安排单左侧「待安排」 | 提供「全部／工单任务／无工单任务」切换。无工单按总任务 → 分工 → 执行人员展开，显示工作项、个人负责范围、关联工站或负责人、其他日期已有安排。候选范围按第8节 |
| 安排单右侧 | 已关联工站的任务进入对应工站；无工站任务进入「无工站 → 当前负责线长」。相同工站内区分工单与无工单卡片。无工单卡片显示工作项、人员、负责范围和安排备注，工单卡片沿用安排数量和单位 |
| 保存确认 | 按新增、修改、取消展示本次变更。工单列出数量变化，无工单列出人员、日期、工站或无工站分组及备注。展示账号实际可保存或发布的范围 |

PMC 操作顺序：

1. 选择执行日期，打开或新建安排单，在左侧切到「无工单任务」。展开任务和分工，勾选一名或多名执行人员。
2. 将选中的人员拖入右侧对应分组。调整排序时记录本地草稿。可以给同一分工的不同人员选不同日期，也可以给同一人员追加其他日期。主单和补充单之间，同一条个人指派在同一天最多一条有效安排。
3. 点「保存到服务器」保留服务器草稿，点「保存并发布／发布」后才形成正式日期安排。已发布安排的修改按原规则保存生效。确认前可返回修改，保存失败保留草稿。放弃本地修改恢复服务器已保存内容。
4. 单据锁定后，如需在允许的时间内为该执行日增加计划，从列表建「补充安排」。取消当天安排时保留取消记录，原任务和个人指派继续有效。改到另一天时区分「改期」和「追加日期」，已锁定日期另行安排。

PMC 维护的是执行日期、当天排序、安排备注及安排的发布和取消。工作项、职责、执行人员、任务原计划日期和关联工站由任务负责人维护，拖拽只改变安排。原有工站滚动、隐藏空工站和定位规则沿用，无工站分组独立展示。打印和 Excel 的无工单输出按第6阶段处理。

### 14.6 后台执行核对、交接与绑定

从安排单列表点「无工单执行查询」，按执行日期查看全日记录。当天没有安排单也可查询。结果按分工、个人指派和执行日期归属，同一分工内已安排和未安排的人员分别显示。

| 分组 | 行内显示 | 可用操作 |
| --- | --- | --- |
| 已安排 | 工作项、人员、工站或负责线长、执行状态、当日用时、核对结果。已安排但未开工的人员也显示 | 查看执行详情 |
| 未安排但有执行 | 实际执行人、工作项、当日用时和核对结果。其他日期有安排或当天有未发布草稿时标明 | 查看详情；有安排权限且日期仍允许时可补充安排 |
| 安排已取消但有执行 | 原安排及取消记录、实际执行状态、当日用时和核对结果 | 查看详情；符合条件时可补充安排 |

1. **PMC 对照计划和实际。** 展开一行查看个人职责、正式安排、当天工作时段和核对结果。补充安排发布后，该人的当日实绩按有效安排重新归类一次，原开工和安排时间保留。没有安排也允许员工按既有规则执行。
2. **任务负责人核对成果。** 在有权限的记录上点「核对」，对照发布时的职责和验收要求，查看员工提交内容、附件和用时，再确认通过、退回补材料或退回补做。时间修正另行核对。负责人本人执行的提交由已指定的核对人处理，整条分工完成按原规则确认。
3. **按授权显示操作。** PMC 的全范围安排权限可查看计划和实际。成果核对按钮需要后台核对权限、有效员工绑定和该任务的具体核对授权。后台账号编辑中的「关联员工」由有账号管理权限的人员维护。执行查询保留「待交接」筛选，交接／指定代管按专门权限操作。
4. **跨日后保留当时结果。** 按北京时间，安排在创建日次日零点锁定，执行结果在执行日次日零点冻结。当天实际工作与当天核对事件分别显示。后续核对、时间修正作为附记，例如同时显示「冻结时待核对」和「次日确认通过」。

### 14.7 典型使用顺序

1. 有效线长或豁免人员建立总任务及分工，明确人员职责；普通线长本人执行时另选核对人，再发布。
2. PMC 在后台统一将各人员安排到具体日期，未安排也不阻挡员工合法执行。
3. 员工分别接收、开工、暂停、提交完成。
4. 各任务负责人按具体任务授权逐人核对，需要时退回补材料或补做。负责人本人执行的记录由指定核对人处理。
5. PMC 按日期对照计划及实际，查出未安排执行或取消安排仍有执行的记录。
6. 跨日冻结结果，后续核对、修正独立附记，任务继续按自身状态流转。
